# ご要望・お問い合わせ: 置き場所の用意（所要 15 分ほど・パソコンなしでもできる）

アプリの中で投稿を受け取り、受信箱で読んで返信します。返信は
**アプリの中（投稿した端末）** と、メールアドレスを書いてくれた人には **メール** の両方で届きます。
利用者はログインしません。ログインするのは管理者（あなた）だけです。

設定が終わるまでは、これまでどおり「メールの下書きが開く」形で動きます。

## 1. プロジェクトを作る

1. <https://supabase.com/> で無料の登録をして、New project。
2. 名前は何でもよい（例: `tenryu`）。データベースの合言葉は控えておく。
3. リージョンは `Northeast Asia (Tokyo)`。

## 2. 表と関数を作る

1. 左のメニュー → **SQL Editor** → New query。
2. `dev/docs/feedback/feedback.sql` の中身をすべて貼る。
3. **上から 9 行目あたりの `<ADMIN_EMAIL>` を、あなたのメールアドレスに書き換える。**
4. Run。`Success` と出れば完了。

## 3. 鍵をアプリに書く

1. 左のメニュー → **Project Settings** → **API**。
2. `Project URL` と `anon public` のキーを写す。
3. `feedback.js` のいちばん上を書き換える。

```js
export const SUPA_URL = 'https://xxxxxxxx.supabase.co';
export const SUPA_KEY = 'eyJhbGciOi...';       // anon public のキー（公開されてよい）
```

## 4. 管理者のログインを作る

1. 左のメニュー → **Authentication** → **Users** → Add user → Create new user。
2. 手順 2 で書いたのと **同じメールアドレス** と、好きな合言葉を入れる。
   `Auto Confirm User` を入にしておく。
3. そのメールアドレスの SHA-256 を作り、`feedback.js` の `ADMIN_HASH` に書く。
   作り方はアプリの中でもできます。ブラウザのアドレス欄に次を貼って実行:

```
javascript:crypto.subtle.digest('SHA-256',new TextEncoder().encode('あなたのメール'.trim().toLowerCase())).then(b=>prompt('',[...new Uint8Array(b)].map(x=>x.toString(16).padStart(2,'0')).join('')))
```

受信箱は、アプリの URL のうしろに `#inbox` を付けて開きます（例:
`https://kokuteki.amaterasu-vocab.com/#inbox`）。一度ログインすると、メニューにも「受信箱」が出ます。

## 5. 返信をメールでも届ける（任意・あとからでよい）

ここを飛ばしても、返信は投稿した端末のアプリの中に届きます。メールでも届けたいときだけ。

1. <https://resend.com/> に登録し、API キーを 1 つ作る。差出人にできるドメインを登録する
   （持っているドメイン `amaterasu-vocab.com` を使うのが確実）。
2. Supabase の **Edge Functions** → Deploy a new function → 名前 `feedback-reply`。
   `dev/docs/feedback/edge/feedback-reply/index.ts` の中身を貼って Deploy。
3. Edge Functions → Secrets に 3 つ入れる。

| 名前 | 値 |
|---|---|
| `ADMIN_EMAIL` | 手順 2 で書いたメールアドレス |
| `RESEND_KEY` | Resend の API キー |
| `MAIL_FROM` | 差出人（例: `TENRYU <support@amaterasu-vocab.com>`） |

4. `feedback.js` の `MAIL_ON` を `true` にする。

## 確かめること（指示書の検収そのまま）

1. メールアドレスを書かずに送る → 送れる。受信箱に「（匿名）」で出て、**メールの宛先がない**と分かる。
2. 受信箱で開くだけ（返信は書かない）→ 利用者の画面に赤い印が付き、**「読みました」**と出る。
3. 返信する → 印が付き直り、返信の本文が出る。**画面を開いた瞬間に印が消える。**
4. 既読のあとにもう一度返信 → **また印が付く。**
5. SQL Editor から、許していない形式の `attachment_data` を直接 insert → 受信箱で
   **リンクにならず**「開けません（形式が不正です）」と出る。
6. 本文に `<script>` を入れて送る → **そのまま文字として**表示される。
7. 2MB を超えるファイルを選ぶ → 送信が止まり、理由が出る。
