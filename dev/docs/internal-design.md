# 航空適性トレーナー 内部設計書

作成日: 2026-09-02　版: 1.0（確定版）

## 1. 目的と構成

航空学生の適性検査（方位判断・姿勢指示器の読み取り・操縦操作の判断）を反復練習する単一ページのブラウザアプリ。
ロジック（出題生成・採点・計器の描画）と見た目（配色・タイポグラフィ・レイアウト）を分離する。

| 層 | 担当 | 成果物 |
|---|---|---|
| ロジック層 | 本設計（コード） | `engine.js` 相当。出題・採点・計器 SVG の生成 |
| 見た目層 | Claude Design に発注 | 画面レイアウト、配色トークン、コンポーネント仕様 |
| アイコン | RIKYU AI に発注 | モードタブ・操作ボタン・方位ボタン等の幾何学アイコン |

ロジック層は CSS 変数（トークン）だけを参照し、色の実値は持たない。見た目層はトークンの値とレイアウトを決める。

## 2. 種目（モード）

| ID | 名称 | 出題 | 回答形式 |
|---|---|---|---|
| `heading` | 1. 方位 | 上面図の戦闘機 + 北マーク | 8方位から1つ |
| `attitude` | 2. 姿勢指示器 | 第三者視点の戦闘機 | 姿勢指示器の4択 |
| `combo` | 1+2. 複合 | 上面図 + 第三者視点 | 姿勢指示器+方位指示器の計器パネル4択 |
| `control` | 3. 操縦操作 | コックピット視界3枚（縦に時系列） | 各区間の操作を6種から選択 |

## 3. 座標と符号の規約

- 方位 heading: 北を 0°、時計回りに正。8方位は 45° 刻み（N=0, NE=45, …, NW=315）。
- バンク bank: 右バンク（右翼が下がる）を正 [°]。
- ピッチ pitch: 機首上げを正 [°]。
- ヨー yaw: 機首が右へ振れる向きを正 [°]。
- 画面角 theta: 画面の上を 0°、時計回りに正。上面図の機体は `rotate(theta)` で描く。
- 北マーク角 phi: 画面の上を 0°、時計回りに正。`heading = (theta − phi) mod 360`。

### 見え方の規約（採点の根拠）

| 機体の動き | 姿勢指示器 | コックピット視界 |
|---|---|---|
| 右バンク | 水平線が右上がり（地面が右で高い） | 景色が左に傾く（水平線が反時計回りに回る） |
| 左バンク | 水平線が左上がり | 景色が右に傾く |
| 機首上げ | 水平線が下がり、空が広がる | 水平線が下がる |
| 機首下げ | 水平線が上がり、地面が広がる | 水平線が上がる |
| 機首右（ヨー） | 方位指示器のみ変化 | 水平線は不変、景色が左へ流れる |
| 機首左（ヨー） | 方位指示器のみ変化 | 景色が右へ流れる |

SVG 実装: 姿勢指示器・視界ともに `rotate(−bank) translate(0, pitch·k)` を地平線グループに適用し、ヨーは地平線上の目印グループを `translate(−yaw·k, 0)` する。

## 4. 出題生成

### 4.1 方位 `genHeading`

- `dir` ∈ 1..7 を一様乱数（`dir = 0` ＝機首が N マークと同じ向き＝答えが自明なので出題しない）。
- 設定「N マークの向き」: 既定はランダムで、8 方位（`phi` ∈ {0,45,…,315}）のいずれか。「上に固定」なら `phi = 0`。
- `theta = phi + dir·45`。
- 正解: `dir`。

### 4.2 姿勢指示器 `genAttitude`（2026-09-02 改訂: 14 方向イラスト方式）

第三者視点は「南からの固定視点」。ブルーインパルスは原点にあり、機首が向く 14 方向のイラスト（ユーザー提供の向き図から切り出し）を 1 枚提示する。

| 方向 | heading | pitch | 方向 | heading | pitch |
|---|---|---|---|---|---|
| 北 | 0 | 0 | 北東上 / 北東下 | 45 | +30 / −30 |
| 南 | 180 | 0 | 北西上 / 北西下 | 315 | +30 / −30 |
| 東 | 90 | 0 | 南東上 / 南東下 | 135 | +30 / −30 |
| 西 | 270 | 0 | 南西上 / 南西下 | 225 | +30 / −30 |
| 上 | なし | +90 | 下 | なし | −90 |

- 読み方: 画面の奥が北、手前が南、右が東、左が西。翼は常に水平（バンク 0）。真下は背面がこちら（南）を向く。
- 図版の生成（最終）: ユーザー提供の 3D モデル `T4blue.fbx`（`t4model/`）を three.js で描画する（`render/render.html` + `tools/render_server.py`）。
  - 座標系: x＝東（右）、y＝北（紙面奥）、z＝上。カメラは南 (0,−d,0) から原点を見る。
  - モデル固有軸（機首 −z、上 +y）を `ax=90`（X 軸回り +90°）で標準状態（機首 +y、上 +z）に合わせる。
  - 方位 h・ピッチ p への姿勢: `R = Rz(−h) · Rx(p)`。斜め方向は h ∈ {45,135,225,315}、p = ±30°（`?dp=` で変更可。45° は急すぎるとの指摘で 30° に決定）。
  - 脚・前脚・開状態のエアブレーキのメッシュは非表示（`ladder` はラダー＝方向舵なので表示する）。脚を隠すと脚収納部の内側（無地材質 `main`）が灰色の板として見えるので、`?paint=main/main/006ab0` で機体下面の青に塗って閉じた蓋に見せる。背景は透明（アプリ側で明るいグレー #cdd3da を敷く）。
  - 材質は両面描画（片面だと垂直尾翼などの薄い面が欠ける）。法線は形状から再計算する（元データの内向き法線が黒い陰影の原因だった）。照明は環境光主体（hemi 2.2 / amb 0.6 / dir 0.9）。
  - 1800×1200 で描画し、14 枚を共通の切り出し枠でトリミングして縮尺を揃え、減色せず WebP（品質 92・透明あり）で `app/img/bi-*.webp` に保存。上面図は `t4-top.webp`。
  - 幾何学的な帰結: 北東下・北西下は腹面が少し見え、南東下・南西下は機首が手前に来るため上面（キャノピー）が見える。
- 旧方式（Gemini 生成の向き図の切り出し `tools/cut_bi14.py`）は保持のみ。
- 正解の姿勢指示器: バンク 0、上表のピッチ。
- 誤答候補: ピッチ反転、バンク ±30 を付けたもの、水平（または ±30）。真上・真下は ±90 と ±30・0 のピッチ違いのみ（バンク違いは見分けにくいため）。
- 選択肢 4 つをシャッフル。

### 4.3 複合 `genCombo`

- 14 方向のうち方位が定まる 12 方向から 1 つ選ぶ。上面図は表示しない（方位もイラストから読む）。
- 誤答候補: `(h+180) (360−h) (h±90) (h±45)` の方位違い、`−pitch` のピッチ違い、バンク ±30、およびその組み合わせ。
- 選択肢は姿勢指示器 + 方位指示器の組で表示。

### 4.4 操縦操作 `genControl`

操作は次の6種のみ。同時操作はなく、複数操作は一つずつ順に行う。

| ID | 表示 | 機体 | 状態変化 |
|---|---|---|---|
| `stick-right` | 操縦桿 右 | 右に傾く | bank += 20 |
| `stick-left` | 操縦桿 左 | 左に傾く | bank −= 20 |
| `stick-forward` | 操縦桿 奥 | 沈む（機首下げ） | pitch −= 8 |
| `stick-back` | 操縦桿 手前 | 上昇（機首上げ） | pitch += 8 |
| `rudder-right` | ヨー 右 | 水平のまま右を向く | yaw += 10 |
| `rudder-left` | ヨー 左 | 水平のまま左を向く | yaw −= 10 |

- 写真は3枚。①が開始状態、①→② と ②→③ の2区間それぞれに操作1つが対応する。
- 設定「操作数」: 単一操作（2区間とも同じ操作を継続）/ 2操作（区間ごとに独立に抽選。同じ操作や逆操作も許す）。
- 設定「①の初期姿勢」: 水平（bank=pitch=yaw=0）/ ランダム（bank∈{−30,−15,0,15,30}, pitch∈{−10,0,10}, yaw∈{−10,0,10}）。
- フレーム: `frames[0] = init`, `frames[t] = frames[t−1] + effect(ops[t−1])`。
- 回答（2026-09-02 改訂）: 操作列を文にした 4 択。「操縦桿を右に倒し、右方向舵を踏む」のように①→②、②→③の順で連用形でつなぐ。単一操作は「操縦桿を右に倒す」。
- 誤答候補: 順序の入れ替え、片方または両方を逆操作にしたもの、片方を別の操作にしたもの、同じ操作の繰り返し。
- 採点: 選んだ選択肢が正解列と一致すれば正解。解説は区間ごとに見え方→機体の動き→操作を示す。
- 表示: 3枚を縦に並べ、①②③のラベルを付ける。

## 5. 描画関数（ロジック層が提供）

すべて純関数で SVG 文字列を返す。SVG は `viewBox` と `width="100%"`（`aspect-ratio` 付き）で出力し、実寸は親要素の幅で決まる。ピクセル指定は行わない。色は CSS 変数。

| 関数 | 引数 | 縦横比 | 内容 |
|---|---|---|---|
| `figTopDown(theta, phi)` | 画面角, 北角 | 1:1 | 方位環 + N マーク + **T-4 上面図イラスト**（`img/t4-top.png`、元絵は機首左向きなので `rotate(theta+90)`） |
| `figDir14(d)` | 14 方向の要素 | 346:148 | **南からの固定視点イラスト**（`img/bi-<id>.jpg`）+ 上/北/東の凡例。ラベル部分は空の色で塗り潰し済み |
| `svgTopDown(theta, phi)` | 画面角, 北角 | 1:1 | （旧）シルエット版。未使用 |
| `svg3D(bank, pitch, front)` | 姿勢, 視点 | 360:250 | （旧）簡易3Dモデル。未使用 |
| `svgAI(bank, pitch)` | 姿勢 | 1:1 | 姿勢指示器。機体シンボル固定、地平線が動く。ピッチ目盛 ±10/20/30、バンク目盛 0/10/20/30/45/60 |
| `svgHI(heading)` | 方位 | 1:1 | 方位指示器。カードが `rotate(−heading)`、N/3/6/E/… の表記 |
| `svgCockpit(bank, pitch, yaw, progress)` | 姿勢+ヨー+前進度 | 3:2 | 風防クリップ内に空・地面・水平線・目印（太陽、山並み、雪山、塔）、固定 HUD。`progress` 0..1 で目印を最大 1.45 倍に拡大（時間が進むと前進して景色が大きく見える）。出題の①②③は 0 / 0.5 / 1 |

3D モデルの視点: 後方は方位角 26°・仰角 18° から見下ろす。前方視点は機体を 180° ヨーさせて同じカメラで描く。

## 6. 状態と永続化

```
state = { mode, question, qcount, answered, t0 }
settings = { north, ops, init, auto, qLimit: 秒(0=なし), sLimit: 秒(0=なし), qCount: 問(0=なし), dirLabel: kanji|alpha, skipExplain, showIntro, showPractice, theme, version }
hideIntro = { <mode>: true }   // 「次回から表示しない」
stats[mode] = { n, c, t }   // 出題数, 正解数, 合計秒
```

- `localStorage` キー `aat.settings`, `aat.stats`, `aat.mode`。読み書きは try/catch で保護。
- タイマーは出題描画完了で開始、回答確定で停止し、秒を stats に加算。

## 7. 画面遷移と操作

画面は 3 つで、URL のハッシュで切り替える（ブラウザの戻るが効く）。

| ハッシュ | 画面 | 内容 |
|---|---|---|
| `#home`（既定） | ホーム | タイトル「TENRYU」と種目カード 4 枚（種目名のみ: 方位／姿勢指示器／方位×姿勢指示器／操縦操作）。右上のメニュー（ホーム／アプリの説明） |
| `#train/<mode>` | 訓練 | 1 種目 = 1 セッション。種目タブはなく途中で切り替えられない。離れるときは確認ダイアログ。制限時間つき（下記） |
| `#settings` | 設定 | 制限時間（1 問あたり: なし/5〜60 秒、種目全体: なし/1〜15 分）、方位の表記（漢字 / アルファベット）、テーマ、出題設定（北の向き・操作数・初期姿勢・自動で次へ） |
| `#about` | 説明 | 箇条書きで簡潔に: アプリの説明、種目、視点と座標、計器と操作、**3D ビューア**、クレジット |

3D ビューア（`viewer.js`、three.js を CDN の importmap で読み込み、説明画面を開いたときだけ動的 import）:
- モデルは `model/t4.glb`（描画ツールの `?export=1` で FBX から変換。脚・開状態エアブレーキを除去、収納部を機体色で塗り、頂点共有化、テクスチャ 1024px、約 4MB）。
- 世界座標は描画ツールと同じ（x 東・y 北・z 上）。カメラは南 (0,−24,0) から原点。OrbitControls でドラッグ回転・ピンチ拡大、パンは無効。
- 14 方向ボタンで `R = Rz(−h)·Rx(p)` の姿勢へ 0.45 秒で補間。「視点を南に戻す」でカメラを初期位置へ。
- 水平面の格子（z=−6）と東（赤）・北（緑）・上（青）の矢印を表示。
- 画面を離れると描画ループを止め、戻ると再開。読み込み失敗時は文言で通知。

セッションと制限時間:
- 1 問の制限時間があるときはカウントダウン表示（残り 3 秒で赤）。0 になると「時間切れ ✗」として不正解扱いで採点し、正解を強調して解説を出す。
- 種目全体の制限時間があるときは種目バー右に残り時間（残り 30 秒で赤）。0 になると回答中なら即終了、回答済みなら「結果を見る」に切り替わり、成績（出題・正解・正答率・平均解答時間）と「もう一度」「ホームへ」を表示する。
- 既定値（本番はスピード勝負）: アルファベット表記、20 問、1 問 5 秒、全体 5 分、解説スキップ。設定に version を持ち、版が変わったら既定値に戻す。
- 解説スキップ: 計測中は正誤の印を 0.45 秒だけ見せて次へ。練習問題では常に解説を表示。
- 出題数: 10/20/30/50/制限なし。達したら終了して成績を表示。

開始の流れ（`enterMode`）:
1. 操縦操作だけは先に「練習／計測」を選ぶ（`#train/control/practice` | `#train/control/measure`）。
2. 説明画面（種目ごとの箇条書き + 制限時間の要約 + 「次回から表示しない」チェック、既定でオン）。設定「開始時の説明を表示」をオフ→オンにすると再表示。
3. 練習 3 問（制限時間なし・解説あり・記録に含めない。設定で非表示可。操縦操作では出さない）。
4. 計測（制限時間・出題数つき）→ 成績。

操縦操作の「操作ごとの見え方」（`#train/control/gallery`）: 操縦桿（左・右・奥・手前の 1 行、排他）と方向舵（左・右、排他）をボタンで選ぶ。操縦桿は一度に 1 方向しか倒せないので、複合パターンは操縦桿＋方向舵の組み合わせだけ。複数選択時は「同時に行う／順番に行う」を切り替え可。順番に行うときは「操縦桿 → 方向舵」「方向舵 → 操縦桿」で先に行う側を選ぶ（順番で結果が変わるため）。選んだ操作の水平①→②→③を縦に並べて表示し、操作ごとの見え方の説明を添える。目印として雪山の頂と塔の先端にオレンジの輪、①の水平線の位置に破線を描く（`svgCockpit` の第 5 引数 `marks`）。未選択でも水平飛行の 3 枚を出し、条件で出る行は薄くするだけで消さないため、選択しても画面がずれない。さらに選択行と 3 枚を 1 画面に収める（スクロール不要）ため、`body[data-phase="gallery"]` で記録チップ・脇のメモ・冒頭説明を隠し、フレームは風防部分だけ（viewBox 360×188 に差し替え）を `calc((100dvh - 31.5rem)/3)` の高さで表示する。375×667 でも収まることを確認済み。

操縦操作の練習（シミュレータ）: 視界と姿勢指示器を表示し、操縦桿（奥/左/右/手前）と方向舵（左/右）のボタンを押している間だけ姿勢が変わる（バンク 45°/s、ピッチ 18°/s、ヨー 25°/s、上限 ±60/±40/±120°）。SVG の `.ck-att` `.ck-yaw` `.ai-h` `.ai-p` の transform を書き換えて更新する。前進の表現として目印の拡大率を 8 秒周期で 1→1.45 倍に変化させる。

1. ホームで種目を選ぶ → セッション開始 → 新規出題。
2. 回答 → 採点 → フィードバック（正誤、経過秒、解説、正解の強調）→「次の問題」。
3. 設定変更は即座に新規出題。設定「正解したら自動で次へ」が ON なら正解時 1.4 秒後に自動出題。

キーボード: 方位はテンキー 8/9/6/3/2/1/4/7（または w/e/d/c/x/z/a/q）、4択は 1〜4、操縦操作は各区間の 1〜6、Enter で回答/次へ。

## 9. 配信形態: PWA（スマートフォン主体）

主な利用端末はスマートフォン。ホーム画面に追加してアプリとして起動できる PWA として配信する。

| ファイル | 役割 |
|---|---|
| `manifest.webmanifest` | 名称、`display: standalone`、縦向き固定、テーマ色、アイコン 192/512（maskable） |
| `sw.js` | サービスワーカー。初回に全ファイルをキャッシュし、以後はキャッシュ優先でオフライン動作。更新時は `CACHE` の版数を上げる |
| `icons/*.png` | アプリアイコン。現在は仮生成品。正式版は RIKYU AI の納品で置き換える |
| `index.html` の meta | `viewport-fit=cover`、`theme-color`、iOS 用 `apple-mobile-web-app-*` と `apple-touch-icon` |

- Android/Chrome: `beforeinstallprompt` を受けて「ホーム画面に追加」ボタンを表示。
- iOS/Safari: 自動インストール不可のため、共有メニューからの追加手順を案内する。
- 配信は HTTPS の静的ホスティング（GitHub Pages 等）。サービスワーカーは HTTPS か localhost でのみ動く。
- 寸法はすべて `%`・`rem`・`vw`・`fr` で指定し、`px` は使わない。タップ領域は最低 2.75rem。
- セーフエリア（ノッチ）は `env(safe-area-inset-*)` で確保する。

## 10. アイコン（RIKYU AI へ発注する幾何学図形）

## 背景の昼／夜（設定 `scene`）

- 設定 `scene: 'auto' | 'day' | 'night'`（既定 `auto`）。`applyScene()` が `body[data-scene]` を付け、`auto` は判定時刻で 5〜7 時を日の出 `dawn`、7〜17 時を昼 `day`、17〜19 時を夕焼け `dusk`、それ以外を夜 `night` とする（手動は昼／夜のみ）。出題の `render()`、シミュレーター開始、見え方の表示、設定変更時に判定し直す。
- 適用範囲: 姿勢指示器・方位×姿勢指示器の機体画像の背景（`.d14` の `--d14bg`）と、操縦操作の視界 `svgCockpit`（出題・練習・シミュレーター・見え方すべて）。姿勢指示器の計器そのものや方位の上面図は変えない。

## 計測条件は種目ごとに開始前に決める（2026-09-03）

- 設定画面から「計測」群と「説明と練習」群を外し、表示（方位の表記・テーマ・背景）だけにした。`SETTINGS_VERSION` を 3 に上げ、旧版の qCount/qLimit/sLimit は捨てる。

## 解説表示のときの図の大きさと自動スクロール（2026-09-03）

- 解説（`.fb.show`）を出すとき、スマホ幅では 1 画面レイアウトの伸縮を止めて通常の流れに戻すが、図の大きさは変えない。`finish()` が直前に `freezeFigs()` を呼び、`.d14`（機体画像）・`.fig.top`（上面図）・`.frame`（視界 3 枚）の高さを inline の rem で固定する（次の出題で図を作り直すので自然に解除される）。以前は自然サイズに戻していたため、操縦操作の 3 枚が解説で少し拡大していた。
- 解説が出たら `revealFeedback()` が画面のいちばん下まで自動で送る（`scrollTo` の smooth、効かない環境では 400ms 後に即時で送り直す）。利用者が自分でスクロールせずに「次の問題」を押せるようにするため。
- 方位×姿勢指示器の選択肢（`.pair`）が iOS Safari で描画されなかった原因は、幅が確定していなかったこと。外側の `svg` は `width:auto` が 100% と同じ扱いになるため、親の幅が `auto`（縮小して合わせる）だと幅を解決できず 0 になる。対策として親に `width:100%`（PC は 92%）、計器に `width:calc(50% - .125rem); height:auto` と、どちらも確定した幅を与える（高さは縦横比から決まるので `dvh` に頼らない）。

## 操縦操作の 2 操作は「操縦桿 → 方向舵」だけ（2026-09-03）

## 方向舵は機体の上下軸まわり（2026-09-03）

- 方向舵は機体の上下軸まわりに効くので、機体が傾いているときは機首が水平面ではなく斜めに振れる。右バンクで右方向舵なら機首はやや沈む。
- `applyOp`（出題の見え方）: 方向舵の操作は `yaw += r·cos(bank)`、`pitch −= r·sin(bank)`。バンク 0 のときは従来どおり。
- `sim3d.js` の飛行モデル: 方向舵入力を機体軸まわりのヨー角速度 `ry` として扱い、`pitch −= ry·sin(bank)·dt`、`heading += ry·cos(bank)/cos(pitch)·dt`（協調旋回の項はこれまでどおり別に足す）。
- 解説: 傾いた状態で方向舵を踏んだ区間は「景色が流れ、少し上がる（機首が沈む）」のように上下の動きも書き、最後に理由の 1 行を足す。

## シミュレーターの姿勢をクォータニオンに（2026-09-03、v02.02）

- 操縦桿の左右で何回でも回れるように、前後で宙返りができるように、姿勢の持ち方をオイラー角（方位・ピッチ・バンク）からクォータニオン `att` に変えた。オイラー角では真上・真下で破綻するため。角度の上限は設けない。
- 操作は機体の軸まわりの回転として掛ける: 機首軸 +y にロール、翼軸 +x にピッチ、上下軸 +z にヨー（右方向舵は −z 回り）。方向舵が傾きに応じて機首を斜めに振る性質は、この扱いで自然に出る（前の版で入れた cos/sin の補正は不要になった）。
- 協調旋回（バンクによる旋回）は世界の上下軸まわりの回転として掛ける。真上・真下付近（|ピッチ| ≥ 70°）では効かせない。
- 表示と計器のための `st.h` `st.p` `st.b` は毎フレーム `readAttitude()` がクォータニオンから取り出す（機首の向きから方位とピッチ、機体の上と右翼から傾き）。
- 天井 `CEIL` を 1400 m から 3000 m に上げた。60 m/s・ピッチ 25°/s だと宙返りの直径は約 275 m なので余裕がある。地面に着いたときは水平に戻す。
- 三人称のカメラは機体の姿勢に沿って後ろ上から追う（`cam.up` も機体の上向き）。宙返り中も機体を見失わない。

## 編隊飛行とスモーク（2026-09-03、v03）

- **視点**: 一人称 / 三人称（後方）/ 三人称（前方）の 3 つ。前方は機首の 36 m 前・5 m 上から機体を見る。どちらの三人称も機体の姿勢に沿って位置を取り、`cam.up` も機体の上向きにするので宙返り中も破綻しない。
- **編隊** `FORMATIONS`: 単機 / 三角形 / 逆三角形 / 四角形 / 一列縦隊。先頭機（利用者が操縦する機体）から見た 2〜6 番機の位置を [右, 前後, 上] (m) で持つ。一列縦隊は後ろほど低い（先頭が一番上）。
- 編隊機は先頭機の軌跡（`hist`、6 秒ぶん）をたどる。後方距離 ÷ 速度 だけ前の状態を取り、そこに左右・上下の差を足す。旋回や宙返りでも隊形が崩れない。
- 2〜6 番機は GLB を複製して作り、垂直尾翼に番号の板（canvas のテクスチャ、左右 2 枚）を貼る。先頭機はモデルの「1」のまま。
- **スモーク**: 粒（`THREE.Points` と自前のシェーダー）。0.05 秒ごとに機体の 4.2 m 後ろに出し、`SMOKE_LIFE = 29` 秒（宙返り 2 周ぶん）かけて薄れながら広がる。1 機あたり 620 粒。
- 出す機体の決まり: 同じ左右の位置に後続がいる機体は出さない（後ろの機体が煙の中を飛ぶため）。単機なら先頭機が出す。三角形・逆三角形・四角形では 6 番機が先頭の真後ろにいるので先頭機は出さない。一列縦隊では最後尾の 6 番機だけが出す。
- 色は 白・ピンク・緑・黄・青・カラフル（カラフルは 1〜6 番機に別々の色）。
- 画面の操作は視界の下の「編隊」「スモーク（色）」の選択と「スモーク」ボタン。PC はスペースで入り切り。選んだ内容は端末に覚える（`aat.simForm` `aat.simColor` `aat.simSmoke`）。

## 編隊はブルーインパルスの隊形にそろえる（2026-09-03、v03.01）

- 名前と並びの出典: https://wporep.com/blueimpluse/blueimpulse-formation/ の一覧（利用者の指定）。
- 6 機: デルタ（1 番機を先頭に三角）、ピラミッド（上から下へ広がる三角）、フェニックス（1 が頭・4 が尾・2/5 が左翼・3/6 が右翼）、グランドクロス（十字）、ダブルライン（3 機ずつ 2 列）、リーダーズ・ベネフィット（1 番機の後ろに横一列）。
- 5 機: 傘型、カシオペア（W 形）。4 機: ダイヤモンド、アローヘッド、フィンガーチップ。

## 視点の見回しと横画面の操作の置き場（2026-09-03、v03.02）

- 視界をドラッグすると視点が動く（`addLook(dy, dp)`）。一人称はカメラの向きに首振りを掛け、三人称は機体のまわりを回る。上下は ±75° まで。視点（一人称・後方・前方）を切り替えると中央に戻る。画面を 2 回叩く（ダブルクリック）でも戻る。
- PC のマウスは、押しただけなら従来どおり方向舵。6px 以上動かすと方向舵をやめて視点の操作に変わる。
- 煙は時間とともに大きく広がる（粒の大きさ 5 → 60、0.6 乗で早めに太る）。出す間隔は 0.04 秒、1 機あたり 780 粒。
- 横画面では操作を右側にまとめる: 上から 視点ボタン・3 つのボタン・編隊とスモークの選択、右下に方向舵、計器はその左。左側は操縦桿だけにする。
- 縦画面の視界は `min-height:15rem` を入れて小さくなりすぎないようにした。

- オブジェクト（山・民家・木・塔）は `props` の入れ物にまとめ、`setProps(on)` で出し入れする。画面の「オブジェクト あり／なし」で切り替え、`aat.simProps` に覚える。地面の格子・滑走路・壁は残す（位置と高さの手がかりになるため）。

- 視点に「地上」を足した（v03.04）。滑走路の東側 (90, −120, 3) に立ち、機体の方を向く。距離に応じて画角を 11〜55° の間で変える（遠いほど狭く＝望遠のように）ので、離れても編隊とスモークの形が分かる。ドラッグで見る向きを変えられ、2 回叩くと機体の方に戻る。

## シミュレーターの操作の整理（2026-09-03、v03.05）

- 開始前に設定画面（`#setup`）を出し、編隊と地上の目印の有無をそこで選ぶ。「はじめる」で `runSim()` が実際の画面を組む。
- 飛行中の操作は、水平に戻す（アイコン）・スモーク（アイコン、入り切り）・スモークの色（選択）だけ。初期位置のボタンは縦画面のときだけ出す（`.portrait`）。計測へ進むは右のボタン。
- 横画面の置き場: 方位指示器は右上、姿勢指示器は上の中央、視点ボタンは下の中央、スモークなどのアイコンは右下（方向舵の上）、操縦桿は左下、読み取り値は左上。
- 画面を 2 回叩くと視点が正面に戻る（指でも判定する）。横画面で左上（ホームボタンのあたり）を叩くと「戻るには縦画面にしてください」と出す。
- 着地したら、その時の姿勢のまま動きを止める（`st.ground` が立つ間は `step` を飛ばす）。「水平に戻す」か「初期位置」で再開する。
- 追従機の尾翼の番号がずれていたのを直した。モデルの複製は元と同じ平行移動を持っているのに、入れ物にも同じ平行移動を掛けていたため、板だけが機体から離れていた。板は平行移動を掛けた別の入れ物に入れる。

- 縦画面は試験対策のシミュレーターとして簡素にする（利用者の指示）。スモークの入り切りと色、前方・地上の視点は横画面のときだけ出す。編隊と地上の目印は開始前の設定画面で選ぶ（縦でも選べるが、遊びの操作は横画面）。

- 編隊は飛びながら変えられる（横画面のアイコン）。アイコンは隊形を点で表した図で、`FORMATIONS[k].offs` から自動で作る（先頭機は橙、上下の広がりが大きい隊形は横から見た図にする）。
- 合流と離脱はなめらかにする: 各機は `join`（0〜1）を持ち、`ENTRY`（先頭機の後ろ 300〜520 m、左右と上下にずらした位置）と所定の位置の間を 4 秒かけて行き来する。`join` が 1 に近いときだけスモークを出す。軌跡は 12 秒ぶん残して、合流位置からでも先頭の航跡をたどれるようにした。

- 尾翼の番号の位置は決め打ちをやめ、読み込んだモデルから実測する（`measureFin`）。「後ろ寄り（前後で後ろ 42% より後ろ）・高い（高さの上 28%）・左右に薄い（全長の 6% 以内）」頂点を集めて囲む箱を作り、その左右の面に番号の板を貼る。板の大きさは箱の短い辺の 62%。モデルを書き出し直しても位置がずれない。

- 横画面の操縦桿は左下の角から少し離す（`.stkwrap` に左 2.25rem・下 1.75rem の余白）。角に寄りすぎると親指が窮屈で、端末の縁にも当たるため。

## 自動操縦（2026-09-03、v03.09）

- 地上から編隊の演技を見るための自動操縦。横画面のアイコンで入り切りする（押すと地上の視点に切り替わる）。入れている間は操縦桿と方向舵の操作は効かない（薄く表示する）。
- 動きは 3 つの繰り返し: 周回（観覧位置のまわり半径 430 m、高度 170 m、22 秒）→ 正面通過（観覧位置の向こう 700 m をねらって通り抜ける、15 秒）→ 宙返り（1 周ぶん、最大 18 秒）。
- 操縦は目標点への追尾: 方位のずれをバンクの目標に（±52°）、高さのずれをピッチの目標に（±16°）変え、それぞれの差から操縦桿の入力を作る。飛行モデルは手で操縦するときと同じものを通すので、編隊も煙も同じように付いてくる。
- 入れたときは観覧位置の南西の空（約 700 m）から演技を始める。

- 地上視点の作り直し（v03.10）: 機体を追いかけない。向きは `gYaw` `gPitch`（自分で決めた方向）＋見回しのドラッグだけで変わる。画角は 42° に固定（距離で寄せるのはやめた。追ってしまって見にくいため）。
- 目の高さは 1.6 m（人の背丈）。立ち位置 `gEye` は 2 回叩いた場所へ移す（`groundMoveTo`）。画面の座標から光線を飛ばし、地面・滑走路・オブジェクト（山・家・木・塔）に当たった点の 1.6 m 上に立つ。当たらなければ「その場所には立てません」と出す。
- 地上視点に入ったときと、立ち位置を移したときだけ、機体の方へ一度向ける（それ以外では自動で動かない）。

- 隊形の変更はすべてなめらかに（v03.11）。各機は「いまの位置」`cur` を持ち、毎フレーム目標の位置へ指数で寄る（時定数 1.4 秒、約 4 秒でほぼ所定の位置）。隊形から外れる機体は `ENTRY`（後ろの遠く）へ向かい、そこへ届いたら消える。目標に落ち着くまでスモークは出さない。機数が変わらない隊形どうしの変更でも、機体が新しい位置へ動いていく。

## 自動操縦の演目（2026-09-03、v03.12）

- 演目は `PROGRAM` の順に繰り返す: 旋回 → 正面通過 → デルタ・ループ → 旋回 → デルタ・ロール → 正面通過 → ハーフ・スロー・ロール → 旋回 → レター・エイト → 正面通過 → バーティカル・クライム・ロール → 旋回 → コークスクリュー → 旋回 → チェンジオーバー・ターン → 空中開花 → レインフォール。名前の出典はブルーインパルスの課目一覧（masdf.com）。
- 機体は 1 機を操縦して編隊が付いてくる作りなので、機体ごとに別々に動く課目（交差・対向）は隊形の変化で表す（チェンジオーバー・ターンは旋回中に一列縦隊へ、空中開花は横一列へ、レインフォールはピラミッドへ）。課目が終わると利用者が選んでいた隊形に戻す。
- 課目ごとの操作: 宙返り＝引きっぱなし 1 周、横転＝右へ 1 周（機首は少し上げ）、半横転＝背面で少し飛んでから戻す、8 の字＝右 1 周・左 1 周、垂直上昇＝引いて 70° 超えたら横転して押し戻す、らせん＝上げながら回り続ける。
- どの課目でも最後に安全の補正を掛ける（110 m より低ければ上げ、1500 m より高ければ下げ）。
- 自動操縦の間は、操縦桿の傾けぐあいが視点の移動になる（機体の操作はしない）。方向舵は隠す。演目の名前を視界の下に出す。

- 演目は実際の課目の説明（masdf.com の各課目のページ）に合わせた（v03.13）。隊形の広がり `formScale` を足し、課目の中で間隔を変える。
  - チェンジオーバー・ターン: 縦隊で入り、正面でデルタに組み替えて大きく旋回。旋回しながら間隔を詰める（1.9 → 1.0）。
  - ワイド・トゥ・デルタ・ループ: 間隔の広いデルタ（2.4 倍）で入り、輪を描きながら詰める。
  - 上向き空中開花: 正面で垂直上昇し、横一列へ大きく開く（3.2 倍）。
  - レインフォール: 輪に入り、機首が真下を向いたあたりでピラミッドへ大きく散開（2.6 倍）。
  - 360 度ターン & ループ: 1 周旋回してから宙返り。

- 技を 1 つだけ出す（v03.14）。横画面の「技」のボタンから課目を選ぶと、その課目の間だけ自動操縦になり（`runManeuver`）、終わると操縦が戻る（`oneShot`）。移動のための旋回と正面通過は一覧に出さない。
- 自動操縦の間も視点は自由に切り替えられる（一人称・後方・前方・地上）。自動操縦のときは操縦桿が視点の移動になり、方向舵は隠れる。

  - `submit_feedback` 送る（本文・名前・メール・添付の形式と大きさをサーバー側でも確かめ、10 分 50 件のあふれ止め）。合言葉を返す。
  - `get_feedback_by_tokens` 自分の投稿と返信を読む（合言葉に一致する行だけ、最大 50）。
  - `mark_feedback_read` 「読んだ」を記録する唯一の経路。
- 指示書に沿った点:
  - 時刻の列を 3 つ持つ（`replied_at` / `admin_read_at` / `user_read_at`）。返信のあとに再返信しても印が付け直せる。
  - 利用者側の印は `max(replied_at, admin_read_at) > user_read_at`、管理者側は `admin_read_at` が空か `created_at` より古いとき。読んだだけでも印が付く。

  - 利用者に見せる文は「返信あり」「読みました」「まだ確認していません」の 3 通りを別々に用意する。

  - 管理者の判定は、画面側はメールの SHA-256（目隠し）。本当の権限は RLS（`is_feedback_admin()`）。
  - メールアドレスがない投稿は、受信箱に「（メールなし）」と出し、返信はアプリの中だけに届くと書く。

- 利用者の作業: セットアップ.md の 1〜4（5 は任意）。

## 自動操縦: 進入・機数・墜落防止（2026-09-03、v03.17）

- **墜落しない**。高さだけで判断すると、低い正面通過（130 m）で引き起こしてしまい、背面のときは引くほど地面に向かう。そこで `safety()` は
  (1) 低くて背面気味（`|bank|>60` かつ `z<220`）なら **まず翼を水平に戻す**、(2) `z + fwd.z*SPEED*6`（6 秒先の高さ）が 120 m を切るか `z<80` なら水平にして引き起こす、の順で効かせる。
  最後の砦として `step()` で、自動操縦中は `z<45` にならない（下回ったら水平に戻す）。自分で操縦しているときは、これまでどおり地面で止まる。
- **技ごとに機数が集まる**。`PROGRAM` の各課目に `form` を持たせ、`beginManeuver()` が いまの隊形によらずその隊形にする（コークスクリューとバーティカル・クライム・ロールは 2 機、レター・エイトとハーフ・スロー・ロールは 4 機、ほかは 6 機）。課目が終われば利用者の選んだ隊形（`userForm`）に戻る。合流は `placeMates` がなめらかに行う。
  隊形に `pair`（2 機）と `trail`（縦隊）を追加。`trail` は チェンジオーバー・ターンが `'line'` という**存在しない名前**を指していた不具合の修正でもある（毎フレーム例外になり、画面が止まって見えていた）。
- **見ている前方で行う**。`eyeDir()` が地上視点の向き（`gYaw - look.y`）を返す。`planEntry()` はその正面 520 m を中心に、機体に近いほうの横 400 m に「門」を置き、`in`（門へ）→ `align`（正面の中心へ）→ `do`（技）の順に進む。旋回だけは `front:false` で、これまでどおり移動に使う。
  進入の途中で見ている向きが 35°より大きく変わったら、進入路を引き直す。
  回る課目（レター・エイト、チェンジオーバー・ターン、コークスクリュー、360 度ターン & ループ）は、`turnSign` で **観覧位置から遠ざかる側へ回る**（近づく側へ回ると頭上を越えて後ろへ抜ける）。
- **どこから来るか分かるようにする**。進入のあいだ `st.cue` に「右手（東）から進入」のように出し（画面の課目名の右に「｜」で続ける）、門の位置に高さ 320 m の柱を立てる（地上視点のときだけ見せる）。
- 自分で操縦していて技を 1 つ選んだときは、地上視点なら進入から、それ以外の視点ならその場で始める（高さが足りなければ `climb` で上げてから）。終わりに `out` で水平に戻してから操縦を返す。
- 確かめ方（`scratchpad/h39/autocheck*.html`、`step()` を直接回す作り）: 通しの演技 900 秒で 地面に着かず 最低高度 143 m、各課目の 74〜100% の時間が視界の正面 70°以内。すべての技を 自分で操縦している状態から 1 つずつ試して、地面に着かず 19〜73 秒で 水平の姿勢で操縦が戻る。

## メニューの折り返し（2026-09-03、v03.18）

- メニュー（`.menulist`）は絶対配置で、置ける幅の元になるのはメニューボタンの幅しかない。そのため幅は `min-width` でしか決まらず、11rem では「ご要望・お問い合わせ」＋赤い印が入らず 2 行に折り返されていた。`min-width` を 13.5rem にし、項目は `white-space:nowrap` にした（360 px の画面でも横にはみ出さないことを実測）。
- お問い合わせの説明文は、原稿の途中で改行していたぶんが画面で余計な空きになっていたので 1 行にまとめた。長い英数字の貼り付けで枠が横に伸びないよう、投稿と返信の本文に `overflow-wrap:anywhere` を入れた。

## 横画面をタブレットでも・近くを飛ぶ演技・画面の拡大（2026-09-03、v03.19）

- **横画面の作りがタブレットで出なかった**。条件が `(orientation:landscape) and (max-height:34rem)` で、タブレットの横（高さ 48〜52rem）は外れていた。条件を `(orientation:landscape) and (max-height:34rem),(orientation:landscape) and (pointer:coarse)` に変える（指で触る画面の横向きなら背が高くても使う）。パソコンは `pointer:fine` なので これまでどおり。CSS 2 か所と JS の `matchMedia` の 3 か所を同じ条件にすること。中の寸法は clamp で書いてあるので、背の高い横画面でも崩れない。
- **演技が遠かった**ので近づけた。`SHOW` の `GATE` 520→300、`SIDE` 400→220、`R` 430→330、`ALT` 170→150。各課目の高さも 2〜3 割 下げた。回る課目は傾きを深くして輪を小さくした（レター・エイト 44→56°、360 度ターン 46→54°、チェンジオーバー 45→52°。輪の半径 = v²/(g·tanφ) なので、56°なら 250 m ほど）。観覧位置からの距離は p90 で 971→823 m、正面 70°以内に入る時間は 88%。
- **頭上通過**（`byover`）を追加。観覧位置の 600 m 向こうを狙って低く（120〜130 m）飛び、通り過ぎたら終わる。低く飛ぶので、地面の備えは「6 秒先の高さが 90 m を切るか、いま 70 m を切るか」に下げた（前は 120/80 で、低い通過のたびに引き起こしていた）。
- **画面の拡大**。`cam.fov = 視点ごとの画角 ÷ 倍率`（`setZoom` / `zoomVal`、1〜6 倍）。2 本の指の間隔で倍率を決める（`sim.pts` に触れている指を持ち、2 本以上なら見回しをやめて拡大に切り替える）。パソコンは Ctrl + ホイール（ホイールだけは操縦桿の前後のまま）。右上に倍率を出し、押すと等倍。視点を変えたときも等倍に戻す。
- 技の一覧は同じ id を 1 つにまとめる（頭上通過と正面通過が演技の中に何度も出るため）。

## スモーク・正面からの進入・視点の自動追従（2026-09-03、v03.20）

- **スモークが細かった**。太さは `gl_PointSize = 太さ × (240 ÷ 距離)` で、物理どおりに書くと遠くでは 1〜2 画素になり見えない。出た直後の太さを 5→6、広がりの効き方を `age^0.6 × 55` から `age^0.5 × 60` に変え、**最小 3 画素・最大 90 画素** の頭打ちを入れた。最小で遠くの演技でも筋が見え、最大で真後ろから見たときに画面を覆わない（上限なしで太さだけ上げると、三人称視点で真っ白になる）。濃さは 1 粒 0.4（重なって濃く見える）。消え方は `(1-age)^1.5`。
- **迫力のある技は正面から**。`PROGRAM` に `entry:'front'` を持たせ、`planEntry()` が門を「正面の 1060 m 先」に置く。そこからまっすぐ向かってきて、技は正面で始まり頭の上へ抜ける。付けたのは 頭上通過・デルタ・ループ・コークスクリュー・バーティカル・クライム・ロール・上向き空中開花・レインフォール。ほかは これまでどおり横から入って正面を横切る。コークスクリューは登りの角度を 22°→16° にして、前へ進む力を残した（真上に上がると頭上を通り過ぎない）。
- **視点の自動追従**（`setFollow` / `followState`、横画面のアイコン `#simFollow`、`aat.simFollow` に記憶）。地上から見るとき、機体の方へ 0.45 秒の時定数で首を回す。切ってあれば これまでどおり自分で向けた方向のまま。入れているあいだは進入の目印（柱）を出さない。実測: 切だと視線と機体のずれは最大 180°、入だと平均 2°・最大 40°。
- **横画面の右に「解き方のメモ」が出ていた**。幅 64rem 以上で `.layout` が 2 段組みになるため、タブレットの横画面で出ていた。`body[data-phase="sim"]` のときは `.card.side` を出さず、1 段組みにする。

## キューピッド・スタークロス・自然な合流（2026-09-03、v03.22）

- **コーク・スクリューの作り直し**。1 機がまっすぐ水平に進み、2 番機がその周りを半径 26 m・1 周 3.6 秒で回る。背中（機体の上）を輪の中心へ向けるため、機体の軸まわりに θ+180° 回した姿勢を与える（実測: 上向きベクトルと中心方向の内積 0.93 ＝ 26/27.8 で、幾何のとおり）。実際の演技では直進する 5 番機が背面で飛ぶ（説明文に添えた）。
- **終わりの判定の符号**。`(機体 − 目)·視線` は「手前が正、越えると負」。`> 300` としていたため、頭上通過とコーク・スクリューが始まった瞬間に終わっていた。`< −300` に直した。
- **描き物の課目**（キューピッド・スタークロス）。編隊の位置合わせでは描けないので、観覧位置の正面の空に面を立て、その上の式のとおりに機体を置く。1 番機（操作する機体）は隠し、2 番機以降で描く（キューピッド 3 機、スタークロス 5 機）。
  - キューピッド: 2 機が中央を上がってから左右のハートの葉を回り、下の尖りで合わさる（`16 sin³t` と `13cos t − 5cos2t − 2cos3t − cos4t` の心臓形）。3 機目が左下から右上へ貫く。
  - スタークロス: 5 機が中心から 5 方向へ開き（花）、そのあと 1 つ飛ばしの頂点へ渡って星形（五芒星）を描く。
  - 姿勢は道の接線を機首、図の中心の側を機体の上に向ける。図に入る前に編隊が組み終わるのを待ち（`matesReady`）、6 秒かけて隊形の位置から図の始点へ寄せる。終わったら、そのときの位置から隊形へ戻す（`endFigure`）。地面より下に来ないよう、図の面の高さと大きさを取ってある（実測の最低高度 182〜239 m）。
- **合流・離脱を自然に**。時定数の指数寄せ（始めが速い）をやめ、14 秒かけて「ゆっくり出て ゆっくり入る」曲線で寄せる。まっすぐ最短で寄らないよう、道のりの 28%（最大 90 m）だけ外へ膨らませる（`startJoin`）。離れる機体は後ろの遠く（620〜960 m）まで下がりきってから消す。
- **頭上を抜けたあとは、いったん離れる**。移動の旋回（`orbit`）の隊形を `solo` にしたので、通過のあと後方で隊形が解け、次の課目までに組み直す。
- **課目の説明**。`PROGRAM` の各課目に `desc` を持たせ、課目が変わったら画面の下に 9 秒出す（`#trickDesc`）。名前と中身は 航空自衛隊の展示飛行の課目紹介と、一般の解説記事を参照した。

## 地上での操作・方位計・正面から入る課目（2026-09-03、v03.23）

- **指を離してもスティックが戻っていなかった**。`sim.stickVec` を離したときに 0 にしていなかったので、自動操縦のあいだ 視点が回り続けていた。
- **地上＋自動操縦のスティックは立ち位置を動かす**（`groundWalk`）。見ている向きを前として前後左右へ 34 m/s。高さは 地面と滑走路への真下向きの当たり判定で決める（山や家には登らない。オブジェクトの上に立つのは、これまでどおり画面を 2 回叩いたとき）。三人称・一人称のときは これまでどおり見回しに使う。スティックの絵は自動操縦のとき丸いつまみにし、見出しを「視点の移動」、目印を 前／後ろ／左／右 に変える。
- **右上の方位計**は、地上から見ているときは「自分が見ている方位」（`st.gh` = `gYaw − look.y`）。ほかの視点では これまでどおり機体の方位。
- **正面から入る課目が、正面から外れていた**。門を正面の線の上に置くと、門で 180 度 向き直すことになり、旋回のふくらみのぶん横へずれる。門を正面の線から 420 m 横・1200 m 先に置き、そこから正面の線に乗り直させる。始める条件も「横のずれ 90 m 以内・向きのずれ 10 度以内・観覧位置の 780 m 手前」にした。コーク・スクリューの 1 番機は、傾き ±16 度までで向きを直す。実測: コーク・スクリューと頭上通過は観覧位置の 21〜22 m のところを通る（前は 187〜249 m 横）。
- **編隊が空中で止まって見えた**。理由は 2 つ。
  1. 後ろへ下がる速さが飛ぶ速さと釣り合うと、世界の中では止まって見える。前後のずれの変化に 30 m/s の上限をかけた（横と上下は速くてよい）。離れる機体は 520 m まで離れたら消す。
  2. 記録した経路より前の位置を求められると、いちばん古い記録の点に貼り付いていた。古い点から後ろへ まっすぐ延ばして置くようにした（`stateAt` の外挿）。
  図を描く課目に入るときも、寄せ元を「編隊で飛び続けていたらいる位置」にして、止まって見えないようにした。

## 目で追う視点と方位計の真ん中（2026-09-03、v03.24）

## 技の途中の壁（2026-09-03、v03.25）

- 自動操縦（通しの演技と、1 つだけの技）のあいだは、壁の枠（`walls`）を出さず、`st.wall` も立てない（「これ以上進めません」を出さない）。

## 追従機の動き・尾翼の番号・キューピッドの矢（2026-09-03、v03.26）

- **追従機が振り回されていた**。編隊機は「先頭機の過去の位置＋横のずれを先頭機の姿勢で回した点」に置いていたので、先頭機が横転すると、離れている機体ほど「腕の長さ × 回る速さ」で飛ばされていた（実測で最大 7594 m/s）。
  - 離れている機体は、姿勢の代わりに「機首の向き（方位と上下）だけ・翼は水平」の置き方に混ぜる。混ぜるのは**角度ではなく位置**（角度を混ぜると、背面のとき ±180° の折り返しで飛ぶ）。混ぜ具合は 70 m から 200 m のあいだで 0→1。
  - そのうえで位置をなます（時定数 0.06〜0.86 秒。近いほど弱く）。
  - 結果: 最大 7594→259 m/s、上位 1% が 188→151 m/s、中央値は 60 m/s（機体の速度そのもの）。
- **合流・離脱の速さ**は、距離に応じて時間をかける（`u.dur = 距離 / 18`、8〜34 秒）。前後の速さに上限をかける方式（角ができる）はやめた。
- **自動操縦の舵をなます**（時定数 0.55 秒）。実機は舵をいきなり一杯には切らない。
- **先頭機から地面へ伸びていた白い線**（高度の目安）を削除。
- **尾翼の番号**。塗装の「1」は尾翼の箱の 前後 0.71〜0.99・上下 0.19〜0.59 にある（実測）。板が小さくて上下がはみ出し、全機「1」に見えていた。板を 0.42 × 0.56（縦長）にし、中心を 0.85 / 0.385 に。色は**機体の絵柄から拾った青**（`finColor`: テクスチャの画素のうち青いものだけを数え、いちばん多い色を採る）。書体は本物と同じく右に傾いた太字。材質は Lambert にして、機体と同じ陰の付き方にする。

## 尾翼の番号・自然な動き・昼の演目（2026-09-03、v03.27）

- **尾翼の番号板が 1 枚も作られていなかった**。`measureFin` が、全体の箱を**世界座標**で作り、頂点は**機体座標**に直してから比べていた。機体は原点から離れた位置で読み込まれるので条件が成り立たず、`finRect` が常に null → `addPlates` が何も作らない → 全機がモデルの塗装の「1」のままだった。全体の箱も機体座標に直して比べるようにした（`Box3.applyMatrix4(inv)`）。実測で `finRect` が [[-0.19,-5.91,0.66],[0.19,-4.76,2.05]]、各編隊機の子が 3 つ（機体＋板 2 枚）になったことを確認。
- **スタークロスは 5 機が 1 本ずつ直線を引く**。実機も、機体は急に折れ曲がれないので、複数機の直線で角ばった星を描く。線を引く区間（`STAR_IN`〜`STAR_OUT`）だけスモークを出し、前後は延長線上を飛んでくる／飛び去る。旋回率 0°/s。
- **キューピッドの道すじを、飛べる形に直した**。
  - ハートの輪郭は 上のくぼみと下の尖りが「尖り」（微分が 0 になる点）で、そのままなぞると曲がりきれない。両端を落とし（t = π−0.38 〜 0.38）、入りと出をまっすぐな線でつなぐ。尖りは 2 機の煙が交わって作られる（実機と同じ）。
  - **道のりで測り直す**（`heartPt` の弧長テーブル）。式のままだと尖りの近くで速さが 0 に落ち、止まって見えた。いまは一定の速さ。
  - 矢は 輪から直線へ 0.18 の区間をかけて混ぜる（折れ曲がり 375°/s → 49°/s）。
  - 実測: 最大の旋回率 49°/s・5.5 G、最低高度 125 m（3 機とも）、速さ 63〜89 m/s。
- **腹で滑る動きをやめた**。図を描くあいだの姿勢を、道の接線ではなく**実際に動いた向き**から決める。寄せているあいだも機首が進行方向を向く。

- **シミュレーターの中はいつも昼**（`runSim` で `body.dataset.scene='day'`）。演目を見せるため。画面を出るときは時刻に合わせた背景に戻る。

## キューピッドの描き方・演目間のスモーク・固まる備え（2026-09-03、v03.28）

## クリスマスツリー・ローパス（2026-09-03、v03.29）

## タイヤはモデルの部品、ライトは主脚の前、蜃気楼（2026-09-03、v03.32）

- **GLB を書き出し直した**（`model/t4.glb?v=2`、5.6 MB）。`render.html?export=1&ax=90&hide=blake_op&paint=main/main/006ab0&maxtex=1024`。前回と違い `landing`（主脚＋前脚）と `front_gear` を残す。GLTFLoader ではこれらは **Group**（材質が複数）で、Mesh の名前は `mesh_5_*` になる → 名前は親までたどって判定する（`gearParts` / `underGear`）。3D ビューア（viewer.js）では脚を隠す。
- **タイヤの出し入れ**は、その Group を各機の `gearSets` の入れ物へ移して `visible` を切り替える。複製は脚を移す前に作る（移してから複製すると複製に脚が入らない）。自作の脚は撤去。
- **着陸灯**は `landing` の頂点から主脚の位置を測って置く。前脚は中心線近くにあるので |x| ≤ 0.6 m を外して左右に分け、各脚の前端 +0.25 m・高さの中央に置く。実測 (±1.57, 0.85, −1.79)。翼端灯は全頂点の x の最大・最小の点（実測 (±4.92, −2.67, −0.72)）に、大きさ 0.7・不透明度 0.55 で控えめに。
- **蜃気楼**は 16×16 のモザイクを描いた板（Sprite、不透明度 0.55）を着陸灯の 2.4 m 前に置き、ローパス中は 3 フレームごとに描き替える。
- **頂点の数**が数万あるので、`push(...配列)` や `Math.max(...配列)` は「呼び出しの上限」で落ちる。ループで求めること（読み込みの中で落ちると、GLTFLoader の onError に吸われて **編隊機が 1 機も作られない**。検証で発覚）。
- ローパスのスモークは 3 粒・2.4 倍のまま（利用者「今のままで良い」）、色は白。

## 機体の乗り換えと、垂直尾翼の番号（2026-09-03、v03.35 / v03.36）

- **乗り換え** `nextSeat()`: `seat`（0 = 1 番機、1〜5 = 編隊機）を、出ている機体だけを飛ばしながら順に回す。視点だけが移り、**操縦・自動操縦は先頭機のまま**。カメラは `seatObj` / `seatQ` / `seatR`（乗っている機体の姿勢）で組む。一人称では乗っている機体の座席だけ隠す（編隊機の座席は読み込み時に `holder.userData.seats` へ覚えておく）。乗り換えたら `camPos` を 0 にして追従の平滑化をやり直す。画面は `#simSeat`（横画面、番号を表示）。
- **蜃気楼**は `treeMode && curView === 'ground'` のときだけ出す（機体近くの視点からは見えない）。
- **垂直尾翼の番号**（利用者「どの機体も 1 番機になっている」「番号板が浮いている」）
  - 板を貼る方式（`numberPlate` / `addPlates`）は撤去。機体から浮き、尾翼の傾きにも沿わなかった。
  - 尾翼の「1」は**尾翼の絵柄ではなく、別の小さな部品（メッシュ `let1`）**だった。絵柄だけ塗り替えても消えない。`findDecals()` で 尾翼の箱の中にある「数字くらいの大きさ」の部品を拾って `visible = false` にする。
  - そのうえで `paintFinNumber()` が、隠した部品の位置（機体座標 y, z）へ 尾翼の絵柄に数字を描く。`finTriAt()` で 左右それぞれの面から「その点を含む三角形」を探し、`uvMap()` で **機体座標 (y, z) → 絵柄の画素 (px, py)** の 2×3 行列を作って `setTransform` に渡す。以後は m 単位で描ける（`scale(h2, -h2)` で上下を機体に合わせる）。
  - **落とし穴**: glTF の絵柄は `flipY = false`。`py = H·(1 − v)` にすると上下が逆さになる。`uvMap(hit, W, H, flipY)` で `flipY ? H − H·v : H·v` を切り替える。
  - 絵柄は `paintedTex`（キー = 元の絵柄の uuid + 番号）で使い回す。塗り替えた絵柄は、その機体の中で**同じ元絵柄を使うメッシュすべて**に差し替える（材質は clone）。
  - `measureFin` は脚（`underGear`）を除いて測る。除かないと箱が下へ伸びて尾翼の判定がずれる。
  - 検証: 編隊機 3 番機の尾翼を左右から接写し、両面とも正しい向きで「4」と読めることを確認。

## オフライン対応・尾翼の番号（作り直し）・一時停止と写真・見え方の「動きで見る」（2026-09-03、v03.37）

### オフラインでも 3D が動く
- **three.js をアプリの中に置いた**（`vendor/three/`: three.module.js, addons/loaders/GLTFLoader.js, addons/controls/OrbitControls.js, addons/utils/BufferGeometryUtils.js, LICENSE）。importmap もそこを指す。CDN のままだと、版を上げるたびに キャッシュから消えて取り直しになる。
- **sw.js は入れ物を 2 つに分けた**。`CACHE`（版ごと。上げると消す）と `BIG = 'aat-big-v1'`（3D モデル。版を上げても消さない）。`activate` は BIG を残す。取り込み先は `BIG_RE`（`/model/` または `.glb`）で振り分ける。
- ページ側で、手が空いたときに `model/t4.glb` を先読みする（`requestIdleCallback`。`saveData` や 2G のときはしない）。

### 垂直尾翼の番号（v03.36 の作り直し）
- 利用者「右翼側からは正しいが左翼側から見ると反転している。位置もずれている」。
- 原因: **尾翼の左右の面は同じ絵柄を左右反転して使っている**。絵柄に数字を描くと、片側を正しくすると反対側は必ず鏡文字になる。元の「1」がそれで平気なのは、別部品（`let1`）だから。
- いまの作り: `let1`（白い板。絵柄なし、47 頂点、左右それぞれに 1 枚ずつ）を隠し、**その頂点から左右それぞれの箱を測って、同じ場所に数字の板を 1 枚ずつ置く**（`setFinNumber`）。板の向きは `makeBasis`（右の面は 機首 +y が右に、左の面は 機首が左に見える）。数字は透明な下地に白で描いた 256×256 の絵（`numberTex`、番号ごとに 1 枚）。`polygonOffset` と 6 mm の浮かせで、面と重なってちらつかないようにする。
- 絵柄を塗り替える仕組み（`finTriAt` / `uvMap` / `paintedTex` / `finColor`）は撤去。

### 追従機のガタつき（編隊機に乗ったときの一人称）
- `stateAt(lag)` が **記録のいちばん近い点をそのまま返していた**。コマの長さは実機では毎回ばらつくので、遅らせた位置が 1 コマぶん（60 m/s なら 1 m）飛び、その機体に乗るとガタガタに見えた。前後 2 点を割って返すように直した（位置は lerp、姿勢は slerp）。
- なますのも「世界の中での位置」から「1 番機から見たずれ」に変えた（`basePos` + `offNow`）。編隊ごと進むぶんを毎コマ引きずらないので、コマのばらつきが速さのばらつきにならない。
- 計測（コマの長さを 0.75〜1.25 倍でばらつかせ、演目 60 秒のあと 50 秒）: 追従機の加速度 p50 122 → 44、p90 480 → 105、最大 1176 → 196 m/s²。通しの演目での最高速度も 267 → 186 m/s。

### 演目の一時停止と写真
- `setPaused / togglePause / pausedState / showing`。一時停止は frame() で `dt = 0` にするだけ（見回し・拡大・視点の切り替えはできる。記録は足さない）。
- 画面を 2 回叩く操作は、**演目の最中だけ**一時停止／再開になる（それ以外は今までどおり、地上では立ち位置、空では視点を戻す）。
- 写真（`#simShot`）: `snapshot()` が描いた直後に `toDataURL` する（描く前に読むと空になる）。操作ボタンや計器は 3D の外にあるので写らない。`<a download>` で保存。

### 見え方（gallery）
- **初期状態**を選べるようにした（水平／右バンク 30／左バンク −30／機首上げ 10／機首下げ −10）。①がその姿勢から始まる。
- **「順番に行う」は削除**（利用者「方向舵から操縦桿の順番は少なくともない。あったとしても同時操作まで」）。複数操作は同時のみ。

## 遠くのスモークを見やすく（2026-09-03、v03.38）

- 利用者「キューピッドとか遠いと地上からだとスモークが細くて見えない。ただ、一人称に切り替えたときに太くなりすぎるときは調節する」。

## 図の形・乗り心地・鑑賞モード（2026-09-03、v03.40）

### 一人称のがたつき（本当の原因）

## ストア用スクリーンショットの撮り方（2026-09-04）

App Store のスクリーンショットは実機ではなく、ヘッドレス Chrome に配信用の画面をそのまま出して撮っている。Apple の現行仕様（App Store Connect ヘルプの Screenshot specifications）で要るのは 2 サイズだけ。

| 用途 | 画素 | CSS の窓 | 倍率 |
| --- | --- | --- | --- |
| iPhone 6.9 インチ・縦 | 1320×2868 | 440×956 | 3 |
| iPhone 6.9 インチ・横 | 2868×1320 | 956×440 | 3 |
| iPad 13 インチ・横 | 2752×2064 | 1376×1032 | 2 |

`--window-size` に CSS の窓を渡し、`--force-device-scale-factor` で倍率をかけると、狙った画素数がそのまま出る。`--screenshot` には Windows の絶対パスを渡す（相対パスだと黙って書かれない）。撮る前に必ず出力先を消しておく。前回の画像が残っていると、失敗しても成功したように見える。

演技（キューピッド・スタークロス）は時間がかかるので、実時間で待つと撮れない。`shots/index_fig.html`（配信物のコピー。`sim3d_shot.js` を読み、`window.__sim` を出し、Service Worker を止めてある）を使い、次の順で進める。

1. 設定 → シミュレーターを開き、`#simTrickMenu [data-id="cupid"|"star"]` を押して課目を選ぶ
2. `#sim` に `uihide` を足す（操作ボタン・スティック・下のバーが消える。写真ボタンと同じ状態）
3. 地上視点＋追従にする
4. `__step(1/60)` を必要な回数だけ回す（キューピッド 3300、スタークロス 3000）。ここで `await` を挟むと仮想時間が尽きて画像が書かれないので、一気に回す
5. 1 フレーム描かせてから撮る

3D モデルは仮想時間の下では読み込みが止まりやすいので、ハーネス側で先に取得しておく。

演技の 2 枚は、画面をそのまま撮るのではなく `snapshot()` の出力そのものを使う（`shots/shotpure.html`）。`snapshot()` は `renderer.render(world, cam)` を撮り直して canvas を PNG にするだけなので、計器・課目の名前と説明・視点の切り替え・戻るボタン・HUD（いずれも DOM）も、操縦桿の重ね描き（別のシーン `overlay`）も入らない。写真は景色だけになる。

## 大きなタブレットで「見え方」の 3 枚が潰れる（2026-09-04、v03.47）

画面幅 64rem 以上（12.9 インチ iPad の横画面など）で、見え方の 3 枚が幅 20 px に潰れていた。

出題画面では 3 枚を横に並べ、番号を絵の下に置くため `@media (min-width:64rem)` で `.frame .n{order:2}` を当てている。見え方は 1 列（番号は左、絵は右）のままなので、`order` で番号が後ろに回ると、自動配置で**絵のほうが 1.25rem の列に入る**。絵の入れ物が 20 px になり、中の SVG も 20 px になっていた。

`.gallery .frame .n{order:0}` を足して、見え方だけ並びを元に戻した。スマホでは 64rem 未満なので、この規則自体が効いておらず、症状も出ていなかった。

- 技・編隊の一覧は、横画面では**画面の右側に立てて出す**（`position:fixed; top:.5rem; bottom:.5rem; overflow-y:auto`）。ボタンの真上に開く作りだと、一覧の高さが画面を越える。

### 視点を操作一覧へ
視界の上に置いていた「一人称／後方／前方／地上」のボタン列をやめ、**操作一覧のアイコン 1 つ**にした（乗り換えと同じで、押すたびに次の視点へ回る）。アイコンは視点ごとに差し替える（機体と目の位置で表す）。縦画面は学習用なので一人称と後方だけを回す。写真にも写らなくなった。

### アイコン
分かりにくかったものを描き直した。水平に戻す＝姿勢指示器の丸、スモーク＝機体と尾を引く波、自動操縦＝破線の輪を回る機体、技＝星つきの一覧、初期位置＝戻る矢印と機体。乗り換えは**垂直尾翼の形の中に番号**を書く。

### 画面を 2 回叩いたとき
演目の最中だけの一時停止をやめ、**いつでも一時停止・再開**にした。前は演目でないときに見回しを正面へ戻していた（利用者の言う「水平」）。その戻す操作と、地上視点での立ち位置の移動は**長押し**（0.62 秒）に移した。2 回そろったら数え直すので、3 回目で戻ってしまうこともない。

### 一人称の計器が機体につかず、視点についてきていた
`mount(container, { onState, view })` と分解して受けていたので、**`opt` という変数が存在しなかった**。計器の位置を知らせる `tellPanel()` は `opt.onPanel` を読むので、毎フレーム何も起きないまま帰っていた（`--ix` / `--iy` が一度も入らず、CSS の既定値 `top:78%` のまま画面に貼りついていた）。`mount(container, opt = {})` に直し、中で分解するようにした。

検証は `shots/instchk3.html`（`--ix`/`--iy` が入るか）と `shots/lookchk.html`（見回しの前後の絵）で行った。仮想時間のヘッドレスでは rAF が進まないので、`__step` を回して確かめる。`__step` に `tellPanel()` を足した。

### 横倒し（バンク 90 度）でガクンとなる
協調旋回を `tan(バンク)` で計算していた。90 度をまたぐと tan の符号が裏返り、頭打ち（±30°/s）と合わさって、**方位の変化率が +30 から −30 へ一気に跳んでいた**（実測 60°/s の跳び）。

翼が出せる力には上限があるので、荷重倍数を 4 G で頭打ちにして
`(9.81/V) × min(4, 1/|cos b|) × sin b`
に変えた。浅いバンクでは `tan b` と同じ値、90 度では最大のまま符号が変わらず、通り過ぎても連続する。同じ計測で跳びは 1.6°/s まで下がった（`shots/rollchk.html`）。

## 一人称に 2 つの見せ方（2026-09-04、v03.49）

一人称を 2 つに分けた。視点のアイコンを押すと、この 2 つが順に出てくる。

| 見せ方 | 機体 | 緑の目盛り | 計器の置き場所 |
| --- | --- | --- | --- |
| 一人称（機内） | 計器盤・操縦桿が見える | 出す | 計器盤の上（`--ix`/`--iy`） |
| 一人称（計器） | 消す（外がそのまま見える） | 出さない | 画面の上（中央と右上） |

「一人称（計器）」は試験の絵と同じ見え方で、姿勢指示器と方位計だけを見て操作を覚えるためのもの。**縦画面ではいつもこちら**にする（端末を縦にしたときも切り替える）。控えは `simFpMode`。

3D 側は `setCockpit(on)`。切ると `cockpit`（自分で足した計器盤と操縦桿）と `plane`（買った機体モデル）の両方を消す。機体モデルの側面パネルは `cockpit` ではないので、これも消さないと外がそのまま見えない。操縦桿の重ね描きと計器盤の位置知らせも、機内のときだけにする。

## 操縦桿は傾けるだけ・技の一覧・乗り換えの計器・演技の近さ・壁（2026-09-04、v03.50）

### 操縦桿を倒すと、方向舵を踏んでいないのに旋回していた

`step()` の協調旋回（バンクに応じて世界の上下軸まわりに機体ごと回す）が、自分で操縦しているときにも効いていた。
実機はこれで正しいが、出題の約束は「操縦桿右 → 右バンク → 景色は左へ傾く」「方向舵右 → 右を向く → 景色は左へ流れる」で、
操縦桿を倒しただけで景色が横へ流れると、方向舵の見え方と混ざって覚えられない。

協調旋回を `auto` のときだけに限った。演技（自動操縦）は目標へ向かうのに旋回が要るので、そちらは実機のままにする。
利用者の判断（2026-09-04）でこの食い違いは残す。演技は「実際に操縦できる動きだけ」という決めからは外れるが、
方向舵だけで曲げると横滑りの平べったい旋回になり、演技として不自然に見えるため。

ヘッドレスでの実測: 操縦桿を右へ 0.6 秒 → バンク 36.1°、そのまま 4 秒で方位の変化 0.00°。方向舵を右へ 2 秒 → 方位 +40.1°（＝20°/s）。

### 技の一覧が閉じられない

横画面（`pointer:coarse`）では `.formwrap .formmenu` が `position:fixed` で画面の右いっぱいに出るので、
技を出すボタンそのものを一覧が覆う。もう一度押して閉じることができず、外を触って閉じる手当ても
編隊のメニュー（`fMenu`）にしか無かった。

一覧の先頭に「閉じる」を置き、外を触ったら両方のメニューを閉じるようにした。
3D の画面は `pointerdown` を自分で処理していて `click` を作らないことがあるので、`pointerdown` の捕捉（capture）で見る。
閉じたその 1 回は `stopPropagation()` で 3D へ渡さない（2 回叩く＝一時停止 と重ならないようにする）。

### 乗り換えたときに、計器が 1 番機の上に出ていた

計器盤の位置を知らせる `tellPanel()` と、操縦桿を重ねて描く `drawStick()` は `cockpit`（1 番機の子）の
世界行列を使っていた。視点だけ 2〜6 番機へ移っても、計器盤の位置は 1 番機のままだったので、
乗り換えると計器が自分の計器盤から外れ、1 番機のところに大きく出ていた。

毎コマ、乗っている機体（`seatObj`）に `cockpit` を付け替えるようにした。複製した機体も同じ平行移動を持っているので、
付け替えるだけで計器盤の位置と操縦席の灯りが正しい機体に移る。
「一人称（計器）」で機体を消すのも、1 番機の固定ではなく乗っている機体にした（`applyBody()`）。
編隊機の表示は `placeMates` が毎コマ決め直すので、消すのは毎コマ行う。
出ているかどうかの判定は `visible` ではなく `userData.shown` を見る（消した自分自身を「いない」と誤らないため）。

なお「他の機体を操縦する」形にはしない（利用者の判断、2026-09-04）。
いまの作りは「先頭機に追従する後続機」なので、視点だけ移して 1 番機を操縦すれば、乗っている機体の動きは
後続機として自然になる。隊形の原点を自分に移すと、前にいる機体が自分に引きずられる（先頭機が後続機に追従する）形になり、
かえって不自然になる。

### 地上から見る演技が遠い

観覧位置まわりの寸法を一段近く・低くした（`SHOW`）。R 330 → 240 m、GATE 300 → 220 m、SIDE 220 → 165 m、
ALT 150 → 120 m、ALT_IN 220 → 170 m。正面から向かってくる課目の門は 900 → 650 m、横のずらしは 420 → 320 m。
課目ごとの高さ（`m.alt`）は 0.78 倍にするが、110 m より下げない（`ALT_MIN`）。
クリスマスツリー・ローパス（110 m）のような低い課目をさらに下げると、墜落を避ける手当て（`safety()` の
`ahead < 90`）が働いて引き起こしてしまうため。

### 壁を広げ、近づくまでは見えないようにする

`LIMIT` を 1500 → 1800 m。壁がいつも見えていると景色が枠に囲まれて見えるので、
カメラからその壁までの距離で濃さを決めるようにした（`WALL_FADE` 400 m より遠いと透明、面に着くと 0.55）。
壁ごとに濃さが違うので、材料は 1 枚ずつ持たせる（`wallMat.clone()`）。格子の繰り返しは 6 → 7（1 目盛りを約 500 m に保つ）。

### 入っているボタンがシミュレーターの中で見分けられない

`.iconbtn.on`（オレンジで塗る）より、横画面のシミュレーター用の
`body[data-view="train"][data-phase="sim"] .iconbtn{background:rgba(28,38,50,.85)}` のほうが強い。
背景は暗いまま、字の色だけ `--on-accent`（ほぼ黒）になるので、**入れると絵柄が消えるだけ**で、
入り切りが見分けられなかった（スモーク・ライト・自動操縦などすべて）。
同じ場所に `…[data-phase="sim"] .iconbtn.on` を足して、シミュレーターの中でもオレンジで塗るようにした。

実測（`getComputedStyle`）: 入 `rgb(240,165,58)`・字 `rgb(11,16,23)`／切 `rgba(28,38,50,.85)`・字 `rgb(233,238,244)`。

### 自動操縦のマークと、方向舵の文字

自動操縦（`#i-auto`）の中の小さな機体の絵をやめ、線画の「A」にした（点線の輪と進む向きの三角はそのまま）。
方向舵のペダルの文字は「左・右」から「L・R」にした（読み上げ用に `aria-label` で「方向舵 左／右」を残す）。
どちらも暫定で、幾何学図形は RIKYU へ発注する決めのままとする。

## 操縦桿は一度に 1 方向だけ（2026-09-04、v03.51）

「左右に倒しただけなのに軌道が円を描く」。物理は正しかった。ヘッドレスで測ると、
`input.x=1`・`input.y=0` を 6 秒（60°/s で 1 回転）続けても、横のずれ 0.00 m・上下のずれ 0.00 m・方位 0.00°で、
**軌道はまっすぐ**（機首軸まわりの回転は進む向きを変えないので当然）。
ところが `input.y=0.15` を混ぜると、同じ 6 秒で横に 22.4 m ずれる。
横転が続いているあいだ、小さな機首上げが機体と一緒に回るので、軌道が螺旋になるため。

原因は画面の操縦桿が 2 軸のアナログだったこと。指で真横に倒したつもりでも前後が混じる。
出題の約束（操縦桿は一度に 1 方向）にそろえ、`setStick()` で **倒した量の大きいほうだけを残す**
（`Math.abs(dx) >= Math.abs(dy) ? dy = 0 : dx = 0`）ようにした。絵の操縦桿（`sim.stickVec`）も同じ値で動かすので、
効いている向きがそのまま見える。キーボード（W/S/A/D）は押した本人の意図なので、そのまま両方効く。

## 演目の直し（2026-09-04、show-fixes）

### 隊形が組めるまで待つあいだに、演技が遠ざかっていた

キューピッドやコークスクリューは、編隊が組めるまで `holdBank(28)` で旋回して待っていた。
バンクを保つだけの旋回は輪の中心が決まっていないので、待つあいだに機体が流れる。
実測すると、レター・エイトを技の一覧から選んだとき、26 秒待つあいだに 1.2 km 流され、
8 の字を観覧位置から **1.5 km 先**で描いていた。地上から見ると豆粒で、何をしているのか分からない。

待ち方を `orbitEye()` に変えた。観覧位置を中心にした半径 `SHOW.R` の輪へ steerTo するので、中心が流れない。
さらに、隊形が要る課目は `gather` の段から始めるようにした（`beginManeuver`）。
組めたら `planEntry` を呼び、門からの進入は飛ばして `align`（正面へ寄せる）へ入る。
すでに観覧位置のそばにいるので、遠くの門へ出直すと 20 秒余計にかかるため。

技をひとつだけ選んだときも、正面へ回り込んでから行うようにした（利用者の指示）。
以前は `curView === 'ground' || !oneShot` という条件で、一人称で技を選ぶとその場で始めていた。

### レター・エイトがねじれる

`hdgSum < 360 ? 56 : -56` で、1 周したところでバンクを +56 から −56 へ切り返していた。
4 機の隊形のまま切り返すので、8 の字は描けても隊形がねじれて見える。

実際のレター・エイトは、3 機が片方の輪を描くあいだに 1 機が離れてもう片方の輪を描く。
1 番機は 1 周だけ（切り返さない）にし、離れる 1 機は式で置くことにした（`placeEight`）。

- 輪の中心は、1 番機の輪と反対側に取る（接する 2 つの輪＝ 8 の字）。半径は旋回の式から出す
  `R = SPEED / ((9.81/V)·n·sin(56°))`
- 輪の上の進み方は `ph = 360(x − 0.2·sin(2πx)/2π)`（x は 1 番機が回った角 / `E8_SPAN`）。
  速さは 1 番機の 0.85〜1.27 倍のあいだをなめらかに動く。急な速度変化を作らないため（利用者の指示）
- `E8_SPAN` は 300°。1 番機が 300° 回るあいだに輪を描き終え、残りの 60° で隊形の位置へ寄せる。
  **3 機が輪を描き終わる前に戻る**
- 出だしと戻りは、隊形の位置との間を `smoothstep` で混ぜる（いきなり飛ばないように）

### 図を描いているあいだに、最初の線が消える

煙の寿命は `SMOKE_LIFE`（29 秒）で全体に一つだった。キューピッドは描くのに 36 秒かかるので、
描き終わる前にハートの描き始めが消えていた。

寿命を粒ごとに持たせた（`alife` 属性）。`emit()` はそのときの `lifeNow` を焼き付ける。
課目の始めに `lifeNow = FIG_LIFE[m.id] || SMOKE_LIFE` とし、
キューピッド 46 秒・スタークロス 30 秒・レター・エイト 44 秒にした。
粒の入れ物は 1 機あたり 1400 個・毎秒 25 個なので、56 秒までなら足りる。

### クリスマスツリー・ローパスのライト

`treeMode` に入った時点でライトが点いていたので、回り込んでいる途中から光っていた。
`treeLit` を足し、観覧位置への方位と機首の向きの差が 30° 以内になってから点けるようにした（利用者の指示）。

### 横画面の「計測へ進む」

横画面は見え方を確かめる画面なので、`.acts.row3` を出さないことにした（縦画面に戻れば出る）。

## 操縦桿を 8 方向にする（2026-09-04、v03.57）

v03.51 では「倒した量の大きいほうだけを残す」ようにしていた（上下か左右のどちらか一方）。
軌道が螺旋を描く問題は消えたが、機首を上げながら横転する、といった同時操作ができなくなっていた。

倒した向きを 45 度ごとに丸める形に変えた（`setStick`）。
真横に倒したつもりで前後がわずかに混じっても真横に丸まるので螺旋にはならず、
斜めに倒したときは 機首上げ下げ と 左右ロール が 0.71 ずつ効く。
絵の操縦桿（`sim.stickVec`）も丸めたあとの値で動かすので、効いている向きがそのまま見える。

実測: (0.9, 0.2) → 真横／(0.9, −0.2) → 真横／(0.7, 0.7) → 斜め（両軸 0.71）／(0.15, 0.9) → 真下。

## 離陸と着陸（2026-09-04、v03.62）

### 滑走路を 2 本にする

2 機ずつ並んで離陸させるため、滑走路を 2 本にした（`RWY_X = [0, -100]`）。
地上視点の立ち位置あてのレイキャストで `runway` を使っているので、2 本を 1 つの入れ物（Group）にまとめてある。
家と木を置かない帯も、2 本とも空ける（`free()`）。

### 地上の並びと、2 機ずつの離陸

地上では 1〜6 番機が 2 本の滑走路に 2 機ずつ、3 列で並ぶ（`GRID`、前後の間隔 46 m）。
`placeMates` は `gmode !== 'fly'` のとき編隊機を消していたが、`groundMates()` で並べるようにした。
着陸してきた機体は、その場から並びの位置へなめらかに寄る。

離陸は `startTakeoff()` で始まり、機体ごとに滑走の状態（`u.tk`）を持つ。
`wait = floor(番号/2) × TK_GAP` 秒だけ待ってから滑走を始めるので、2 機ずつ 7 秒おきに上がる。
浮いたあとは `TK_ANG`（9°）で上昇し、`TK_UP`（70 m）を超えたところで、
そのときの位置を 1 番機から見たずれに直して `u.cur` に入れ、ふつうの編隊の置き方に返す。
そこから `startJoin` の道引きが働いて、隊形に入っていく。

1 番機（操縦している機体）の離陸は、もともとある `groundStep` の `takeoff` に任せる。
全機が編隊へ移ったら脚をしまう。

### 演目の始めと終わり

`setAuto(true)` を地上の待機中に押すと、離陸から始める（`gmode='takeoff'` と `startTakeoff()`）。
飛んでいるときは、これまでどおり空から始める（利用者の判断）。
課目を一周したら `beginLanding()` に入り、縦隊に組み替えて滑走路の南 1100 m から進入し、滑走路の上へ降ろす。
接地の判定は `step()` のふつうの処理（z <= 3.2）に任せる。そこから減速・誘導路・待機まではすでにある。

着陸の段では `safety()`（地面回避）を呼ばない。呼ぶと引き起こされて降りられない。
自動操縦の高さの下限（`st.z < 45` で持ち上げる最後の砦）も、着陸の段だけ外す。

### 固定モード（自動操縦を 2 回押す）

`showLoop` が true のあいだは、離着陸を含めずに課目を繰り返す。
自動操縦のボタンを 450 ms 以内に 2 回押すと切り替わる（枠が太くなる `.iconbtn.loop`）。

体験版では、この固定を「地上から全部の演目を映すだけ」の形にする（利用者の指示）。
`setAllowed(null)` で課目の制限を外し、`setProps(false)` でオブジェクトを消し、
地上視点にして機体を目で追い、操作をしまう。自動操縦を切ると元に戻る。

### 隊形が整うまでスモークを出さない

離陸して集まってくるあいだは、煙を出すと空が汚れて何をしているのか分からない。
`forming`（離陸の最中か、1 番機から 130 m より遠い編隊機がいる）のあいだは出さないことにした。
隊形の中で位置を入れ替えているだけのとき（近い）は、これまでどおり切らずに出す。

## v03.75 音は再生中だけ、固定は着陸してから離陸で始め直す

- **音は再生中のみ**。一時停止と、ほかの画面を見ているあいだ（`document.hidden`）は
  音の仕組みごと止める（`audioHold()` で `AudioContext` を suspend / resume）。
  機体の通過音も曲もまとめて止まるので、消し忘れが起きない。
- **自動操縦のボタンは、操作をしまったあとも残す**（`.showui`）。
  しまうのは押してから 0.7 秒後にする。すぐしまうとボタンの位置が動いて、
  2 回目のタップ（固定）ができないため。2 回目が来たら、しまうのを取り消す。

### 課目
- **レインフォール**: 捻れない。60 度より立ったら横の舵を打たない（傾きの読みが定まらず、直そうとして捻れていた）。
  実測 鉛直のあいだの傾き 0.007 度。南から北へ向かい、散開位置の真上で押し下げる。
  押して降りると引き起こしは来た向きへ戻るので、南から来れば原点の側へ抜ける（北から来ると北へ抜けてしまった）。
  実測: 線の上（左右 0）で 640 m 付近から鉛直、引き起こしのあと 奥 531 → 128（南へ）、高さ 139〜149 m。
- **タック・クロス**: 散開位置（600 m）まで背面で線の 30 m 西を直進（相手は鏡で 30 m 東・14 m 上）。
  散開位置で 1.2 秒かけて右 50 度へ戻し（南向きでは西へ膨らむ）、膨らみ 60 m → 交差点（線の 40 m 東・300 m）へ。
  交差点を通ったら、その瞬間の速度ベクトルのまま直進。実測: 線を横切るのは 奥 202 m、終わりは南東（方位 160）、55 秒。
  捕まえる半径を 40 m にすると通り過ぎてから戻ろうとして輪を描く（実測）。膨らみを大きくしても曲がりきれずすれ違うだけ。
- **チェンジオーバー・ターン**: 北東（45 度・1300 m）から頂点（原点と散開位置の中間・300 m）へまっすぐ、
  頂点で交互に開いてデルタになり、南東へ曲がったら舵を中立にして速度ベクトルのまま無限遠へ。
  実測: 頂点 奥 284・左右 10、その後 方位 158 で直進、53 秒。捻れなし（舵は頂点の 1 回だけ）。
- **レター・エイト**: 3 機の輪は 1 機の輪の 2 倍（`rS = R / 2`）。1 機は自分の輪を同じ速さで描き、
  描き終えたら 1 番機の通った道（`stateAt(lag)`）に沿って、遅れを 1 秒あたり 0.35 秒ずつ縮めて追いつく。
  実測: 輪のあいだ 60 m/s、追いつくあいだ **81 m/s で一定**。描き物なので `figAim` を付け根に置き、視線は絵を見る。
  煙は 75 秒残す（`FIG_LIFE.eight`）。開き始める位置は散開位置と原点の中間。
- **オポジット・コンティニュアス・ロール**: 東（300 m 北の線上・1920 m 東）から西向きに、
  水平のまま高速（1.4 倍）で入る。相手は鏡（西から東向き）。原点と散開位置の中間で交差した瞬間に
  まず機首を 30 度上げ、そのあと舵を中立にして連続ロール（引き続けると舵の向きが回って進路が流れる）。
  ロール中は傾きで向きを変えない（`noTurn`）。実測: 進入中 傾き 0・高さ一定、交差 奥 274、
  ロール中の北への流れ 66 m / 1.4 km（前は 950 m）、西の無限遠で終わり。
- **サンライズ**: 中央の 2 機も外側と同時に開く（`BLOOM_LAG = 0`）。実測 1696 → −303、左右 0。

### ライト・視点
- ライトは標準でオフ。離陸中（`startTakeoff`）と着陸、クリスマスツリーだけ点け、離陸後はタイヤと一緒に自動でしまう。
  実測: 待機 off / 滑走 on / 上空 off。
- 地上から見るときの「初期位置に戻す」は、立ち位置と向きを原点（北向き）へ戻す（`groundReset()`）。

## v03.83 散開したまま遠くへ、機首の先端を扇の弧に

- **レインフォール**: 散開したあと、1 番機も僚機も進路を保ったまま無限遠まで飛ぶ。
  引き起こしが終わったら舵を中立にし（`holdBank(0)`）、1 番機が見えない距離（`JUMP_FAR`）まで
  離れてから課目を終える。そこで編隊に戻しても遠すぎて見えないので、瞬間移動には見えない。
  実測: **1 コマの飛び 0 m**（編隊へ戻す動きなし）、終わりは 1 番機が 奥 −1800 m、
  僚機は原点から 2028〜2690 m。開いた点からの距離は 5 機とも同じ割合で伸び続ける。
- **サンライズ**: 機首の先端がひとつの弧（＝扇）に並ぶよう、曲がる角の大きい機体ほど少し速く飛ぶ。
  弧の長さが同じでも、曲がる角が大きいほど弦（開いた点からの直線距離）は短くなるので、
  その比 `(θ/2)/sin(θ/2)` を速さに掛ける（90 度 → 1.11 倍、45 度 → 1.03 倍）。
  実測: 開いた点からの距離は 外側 731 m・中央 702 m・1 番機 699 m。
  隊形のもとの前後差（外側 32 m・中央 16 m 後ろ）を引くと 699 / 686 / 699 で、**差は 13 m（1.9%）**。

## v03.84 レター・エイトの作り直し

- **円の大きさと速さ**: 3 機の円は 1 機の円の 1.5 倍（`E8_RAD`）。3 機はふつうの 0.75 倍（45 m/s、`E8_SLOW`）、
  離れた 1 機は 87 m/s（1.45 倍）。速さが落ち着いてから円に入る。
- **傾きは 42 度**（`E8_BANK`）。深く倒すと円が小さくなって 1 周が短くなり、
  1 機が 3/4 までに追いつくのに 2 倍を超える速さが要る。浅く倒して円を大きくすると、無理のない速さで間に合う。
  実測: 半径 229 m、1 周 32 秒。
- **合流**: 1 機は自分の円を 1 周（3 機が 130 度 回るあいだ）し、そこから 3 機の通った道（`stateAt(lag)`）を
  たどる。遅れを縮める速さは「3 機が 270 度 に来るまでの残り時間」から毎コマ決める（上限 `E8_VMAX`）。
  実測: 離れる距離は最大 639 m、3 機の円の 3/4（約 30 秒）で 34 m まで縮まってダイヤモンドになる。
  1 機の速さは 87 → 85〜89 → 45 m/s と、止まったり下がったりしない。
- **つなぎ**: 自分の円の上の位置と 3 機の道の上の位置は、隊形のずれのぶんだけ離れている。
  そのまま移すと 56 m 飛ぶので、2 秒かけてつなぐ（実測 **1 コマの飛び 0 m**）。
- **スモーク**: 合流したところで先頭機と入れ替える（`smokeOnArr[0] = false`、離れていた機を true）。
  実測 30.1 秒に `111100` → `011100`。
- **終わり**: 円を 1 周したら x 軸を負の向き（南）へまっすぐ進み、見えない距離まで離れたら
  一斉にスモークを切って（`smokeNone`）2 秒後に課目を終える。実測 終わり 奥 −1924 m、72.5 秒に `000000`。

## v03.85 2 機ずつの着陸、立体音、通信の決まり

### 着陸（自動操縦）
- 2 機ずつ、間をあけて 2 本の滑走路へ降りる。1・2 番機 → 3・4 番機 → 5・6 番機。
  出番が来るまでは滑走路の南で輪を描いて待ち（高さは組ごとに変える）、
  1 番機が接地してから `LAND_GAP`（18 秒）ずつあけて降りる。
  1 番機の組は、1 番機が進入に乗って低くなってから一緒に降りる。
- 僚機の進入は `flyMateTo`（一定の速さ・曲がりは制限つき・高さはなめらか）で組み立てた。
  高さは「接地する点までの距離 × 3 度の勾配」で決める。「もう北にいるから」で最終へ移すと、
  斜めから突っ込んで滑走路の帯を外れる（実測 x = 208 m）。進入の線に乗る点まで行ってから最終へ移す。
- 実測の接地点: 1 番機 (20, −403)、2 番機 (−101, −375)、3 番機 (−1, −334)、4 番機 (−100, −374)。
  滑走路は x = 0 と −100 の 2 本（幅 48 m、y = −550〜550）なので、**すべて滑走路の上**。
  接地の間隔は 1 番機 88 秒 → 2 番機 104 秒 → 3・4 番機 117・122 秒。
- 視線は、いま降りている組へ向ける（`figAim`）。

### 離陸の合図
- 浮くタイミングは設定（既定 13.0 秒）で決める。自動で探した値は目安として返すだけにした。
  実測: 自動では 9.0 秒と出る曲でも、設定の 13.0 秒で浮く（曲から **13.1 秒**）。

### 音
- 飛行音を立体音（`PannerNode`・HRTF）にした。聞く人の位置と向きを毎コマ視点に合わせるので、
  イヤホンだと前後左右が分かる。使えない端末では、これまでどおり左右だけの振り分け。
- 止まっている機体は音を出さない（速さ 12 m/s より遅いと、だんだん静かに）。

### 視線と距離
- 遠くへ離れて正面へ移るとき、地上の視線は追いかけない。7 秒かけて 14 度/秒 でゆっくり向き直す
  （まわりを回っていったように見せる）。
- 「無限遠」は、もとの壁のあった位置（`REAR_END` = 原点から 1680 m）にそろえた。
  レター・エイトのスモークを一斉に切るのも、この位置。

### 通信
- 既定では Wi-Fi のときだけ通信する（`netOK()`）。お知らせの取得・更新の確認・3D モデルの先読みを止める。
  回線の種類が分からない端末（iPhone など）は判断できないので通信してよいことにする。
  通信を節約する設定（saveData）が入っていれば、どの回線でも止める。設定「通信」で「いつでも」にできる。

## v03.86 演目の正面を東西南北から選ぶ

- **正面は北に固定しない**。課目を始めるとき、機体がいる方角（進入の点の方角ぶんをずらして）に
  最も近い東西南北を正面に選ぶ（`showFr`）。そちらから入れば回り込みが短い。
  滑走路を使う課目（タッチ・アンド・ゴー、離陸、着陸）は選ばない（滑走路は北向き）。
- 位置はすべて「前へ何 m・右へ何 m」で表し、`showPt` / `showLocal` / `keyPt` で世界の座標と行き来する。
  `eyeDir()` も正面の向きを返すので、正面から入る課目・回り込み・鏡はそのまま回る。
  北を決め打ちしていたところ（レインフォールの進入と引き起こし、タック・クロスの背面の向きと通過点、
  オポジットの左右、チェンジオーバーの頂点、レター・エイトの直進）を正面基準に直した。
- 実測（離陸のあと 6 課目を続けて）: 正面は 0 → 180 → 270 → 0 → 90 → 270 と課目ごとに変わり、
  正面基準の開始位置は 正面の課目 1696〜1917 m・横 0 m、オポジット 前 299 m・右 2195 m、
  レインフォール 後ろ 1477 m、チェンジオーバー 右前 45 度。**形はどの向きでも同じ**。
- **合間を短く**: 門のある課目は隊形が組めるのを待たずに離れ始め（離れながら組む）、
  1000 m（`JUMP_FAR`）まで離れたら進入の線の遠くへ位置を移す（組めてから）。
  実測の進入時間: 62 / 54 / 28 / 43 / 43 / 43 秒（前は 95 / 98 / 58 / 85 秒）。
  終わりとスモークオフの位置（`REAR_END`、壁のあった 1680 m）は変えていない。
- 演目の原点は、自分で向きを決めて見ているときも決まった座標（GROUND_EYE）。視点（立ち位置）には合わせない。

## v03.87 離陸直後の瞬間移動、加速ボタン、コックピットの計器、音の復帰

- **離陸直後の瞬間移動**: `JUMP_FAR` を 1000 m にしたところ、離陸して上がりきった直後（原点から 1 km ほど）に
  目の前で位置が移ってしまった。壁のあった距離（`REAR_END` 1680 m）に戻した。
  実測: 最初に位置を移すのは浮いてから 65 秒後（飛び去ってから）。
- **加速ボタン**: 押したら「曲に合わせて待機中…」、滑走中は「加速中…」と出して押せなくする（`st.waiting`）。
  実測: 押す前 押せる → 直後 待機中（押せない）→ 6 秒後 加速中（押せない）→ 15 秒後 浮いて消える。
- **コックピット視点の計器**: 放置で操作をしまうときも、一人称なら計器（HUD・姿勢計）は残す（`.restfp`）。
  実測: 11 秒後 操作列 0・HUD 1・姿勢計 1。
- **音の復帰**: 別のアプリから戻ると音の仕組みは止まったまま（suspended）か、iPhone では割り込まれた
  （interrupted）状態になる。「running でなければ起こす」に統一し、触れるたびに `wakeAudio()` で起こし直す
  （前は一度きりの pointerdown だった）。

## v03.88 オポジットは交差直後に高速でロール

- 交差した直後、まず機首をいっぱいに引いて 30 度へ（約 1 秒）、上がったら舵を中立にして
  ふつうの 2.2 倍（`OPRO_ROLL`、132 度/秒）で連続ロール。`rollBoost` を step() の横転の速さに掛ける。
- 回しながら引くと、舵の向きが回って機首が上がらない（実測: 機首が ±8 度で振れるだけ）。
  先に上げてから回すと、機首は 2 秒で 36〜37 度に達してそのまま。
- 実測: 交差 2 秒後からのロール速さ 平均 131 度/秒（最大 147）、進路は左へまっすぐ
  （横 −175 → −1368 m のあいだに前後のずれ 125 m = 5 度）。
