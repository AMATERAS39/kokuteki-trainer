# 航空適性トレーナー 内部設計書

作成日: 2026-09-02　版: 1.0（確定版）

## 1. 目的と構成

航空学生の適性検査（方位判断・姿勢指示器の読み取り・操縦操作の判断）を反復練習する単一ページのブラウザアプリ。
ロジック（出題生成・採点・計器の描画）と見た目（配色・タイポグラフィ・レイアウト）を分離する。

| 層 | 担当 | 成果物 |
|---|---|---|
| ロジック層 | 本設計（コード） | `engine.js` 相当。出題・採点・計器 SVG の生成 |
| 見た目層 | Claude Design に発注 | 画面レイアウト、配色トークン、コンポーネント仕様 |
| アイコン | RIKYU AI に発注 | モードタブ・操作ボタン・方位ボタン等の幾何学アイコン |

ロジック層は CSS 変数（トークン）だけを参照し、色の実値は持たない。見た目層はトークンの値とレイアウトを決める。

## 2. 種目（モード）

| ID | 名称 | 出題 | 回答形式 |
|---|---|---|---|
| `heading` | 1. 方位 | 上面図の戦闘機 + 北マーク | 8方位から1つ |
| `attitude` | 2. 姿勢指示器 | 第三者視点の戦闘機 | 姿勢指示器の4択 |
| `combo` | 1+2. 複合 | 上面図 + 第三者視点 | 姿勢指示器+方位指示器の計器パネル4択 |
| `control` | 3. 操縦操作 | コックピット視界3枚（縦に時系列） | 各区間の操作を6種から選択 |

## 3. 座標と符号の規約

- 方位 heading: 北を 0°、時計回りに正。8方位は 45° 刻み（N=0, NE=45, …, NW=315）。
- バンク bank: 右バンク（右翼が下がる）を正 [°]。
- ピッチ pitch: 機首上げを正 [°]。
- ヨー yaw: 機首が右へ振れる向きを正 [°]。
- 画面角 theta: 画面の上を 0°、時計回りに正。上面図の機体は `rotate(theta)` で描く。
- 北マーク角 phi: 画面の上を 0°、時計回りに正。`heading = (theta − phi) mod 360`。

### 見え方の規約（採点の根拠）

| 機体の動き | 姿勢指示器 | コックピット視界 |
|---|---|---|
| 右バンク | 水平線が右上がり（地面が右で高い） | 景色が左に傾く（水平線が反時計回りに回る） |
| 左バンク | 水平線が左上がり | 景色が右に傾く |
| 機首上げ | 水平線が下がり、空が広がる | 水平線が下がる |
| 機首下げ | 水平線が上がり、地面が広がる | 水平線が上がる |
| 機首右（ヨー） | 方位指示器のみ変化 | 水平線は不変、景色が左へ流れる |
| 機首左（ヨー） | 方位指示器のみ変化 | 景色が右へ流れる |

SVG 実装: 姿勢指示器・視界ともに `rotate(−bank) translate(0, pitch·k)` を地平線グループに適用し、ヨーは地平線上の目印グループを `translate(−yaw·k, 0)` する。

## 4. 出題生成

### 4.1 方位 `genHeading`

- `dir` ∈ 1..7 を一様乱数（`dir = 0` ＝機首が N マークと同じ向き＝答えが自明なので出題しない）。
- 設定「N マークの向き」: 既定はランダムで、8 方位（`phi` ∈ {0,45,…,315}）のいずれか。「上に固定」なら `phi = 0`。
- `theta = phi + dir·45`。
- 正解: `dir`。

### 4.2 姿勢指示器 `genAttitude`（2026-09-02 改訂: 14 方向イラスト方式）

第三者視点は「南からの固定視点」。ブルーインパルスは原点にあり、機首が向く 14 方向のイラスト（ユーザー提供の向き図から切り出し）を 1 枚提示する。

| 方向 | heading | pitch | 方向 | heading | pitch |
|---|---|---|---|---|---|
| 北 | 0 | 0 | 北東上 / 北東下 | 45 | +30 / −30 |
| 南 | 180 | 0 | 北西上 / 北西下 | 315 | +30 / −30 |
| 東 | 90 | 0 | 南東上 / 南東下 | 135 | +30 / −30 |
| 西 | 270 | 0 | 南西上 / 南西下 | 225 | +30 / −30 |
| 上 | なし | +90 | 下 | なし | −90 |

- 読み方: 画面の奥が北、手前が南、右が東、左が西。翼は常に水平（バンク 0）。真下は背面がこちら（南）を向く。
- 図版の生成（最終）: ユーザー提供の 3D モデル `T4blue.fbx`（`t4model/`）を three.js で描画する（`render/render.html` + `tools/render_server.py`）。
  - 座標系: x＝東（右）、y＝北（紙面奥）、z＝上。カメラは南 (0,−d,0) から原点を見る。
  - モデル固有軸（機首 −z、上 +y）を `ax=90`（X 軸回り +90°）で標準状態（機首 +y、上 +z）に合わせる。
  - 方位 h・ピッチ p への姿勢: `R = Rz(−h) · Rx(p)`。斜め方向は h ∈ {45,135,225,315}、p = ±30°（`?dp=` で変更可。45° は急すぎるとの指摘で 30° に決定）。
  - 脚・前脚・開状態のエアブレーキのメッシュは非表示（`ladder` はラダー＝方向舵なので表示する）。脚を隠すと脚収納部の内側（無地材質 `main`）が灰色の板として見えるので、`?paint=main/main/006ab0` で機体下面の青に塗って閉じた蓋に見せる。背景は透明（アプリ側で明るいグレー #cdd3da を敷く）。
  - 材質は両面描画（片面だと垂直尾翼などの薄い面が欠ける）。法線は形状から再計算する（元データの内向き法線が黒い陰影の原因だった）。照明は環境光主体（hemi 2.2 / amb 0.6 / dir 0.9）。
  - 1800×1200 で描画し、14 枚を共通の切り出し枠でトリミングして縮尺を揃え、減色せず WebP（品質 92・透明あり）で `app/img/bi-*.webp` に保存。上面図は `t4-top.webp`。
  - 幾何学的な帰結: 北東下・北西下は腹面が少し見え、南東下・南西下は機首が手前に来るため上面（キャノピー）が見える。
- 旧方式（Gemini 生成の向き図の切り出し `tools/cut_bi14.py`）は保持のみ。
- 正解の姿勢指示器: バンク 0、上表のピッチ。
- 誤答候補: ピッチ反転、バンク ±30 を付けたもの、水平（または ±30）。真上・真下は ±90 と ±30・0 のピッチ違いのみ（バンク違いは見分けにくいため）。
- 選択肢 4 つをシャッフル。

### 4.3 複合 `genCombo`

- 14 方向のうち方位が定まる 12 方向から 1 つ選ぶ。上面図は表示しない（方位もイラストから読む）。
- 誤答候補: `(h+180) (360−h) (h±90) (h±45)` の方位違い、`−pitch` のピッチ違い、バンク ±30、およびその組み合わせ。
- 選択肢は姿勢指示器 + 方位指示器の組で表示。

### 4.4 操縦操作 `genControl`

操作は次の6種のみ。同時操作はなく、複数操作は一つずつ順に行う。

| ID | 表示 | 機体 | 状態変化 |
|---|---|---|---|
| `stick-right` | 操縦桿 右 | 右に傾く | bank += 20 |
| `stick-left` | 操縦桿 左 | 左に傾く | bank −= 20 |
| `stick-forward` | 操縦桿 奥 | 沈む（機首下げ） | pitch −= 8 |
| `stick-back` | 操縦桿 手前 | 上昇（機首上げ） | pitch += 8 |
| `rudder-right` | ヨー 右 | 水平のまま右を向く | yaw += 10 |
| `rudder-left` | ヨー 左 | 水平のまま左を向く | yaw −= 10 |

- 写真は3枚。①が開始状態、①→② と ②→③ の2区間それぞれに操作1つが対応する。
- 設定「操作数」: 単一操作（2区間とも同じ操作を継続）/ 2操作（区間ごとに独立に抽選。同じ操作や逆操作も許す）。
- 設定「①の初期姿勢」: 水平（bank=pitch=yaw=0）/ ランダム（bank∈{−30,−15,0,15,30}, pitch∈{−10,0,10}, yaw∈{−10,0,10}）。
- フレーム: `frames[0] = init`, `frames[t] = frames[t−1] + effect(ops[t−1])`。
- 回答（2026-09-02 改訂）: 操作列を文にした 4 択。「操縦桿を右に倒し、右方向舵を踏む」のように①→②、②→③の順で連用形でつなぐ。単一操作は「操縦桿を右に倒す」。
- 誤答候補: 順序の入れ替え、片方または両方を逆操作にしたもの、片方を別の操作にしたもの、同じ操作の繰り返し。
- 採点: 選んだ選択肢が正解列と一致すれば正解。解説は区間ごとに見え方→機体の動き→操作を示す。
- 表示: 3枚を縦に並べ、①②③のラベルを付ける。

## 5. 描画関数（ロジック層が提供）

すべて純関数で SVG 文字列を返す。SVG は `viewBox` と `width="100%"`（`aspect-ratio` 付き）で出力し、実寸は親要素の幅で決まる。ピクセル指定は行わない。色は CSS 変数。

| 関数 | 引数 | 縦横比 | 内容 |
|---|---|---|---|
| `figTopDown(theta, phi)` | 画面角, 北角 | 1:1 | 方位環 + N マーク + **T-4 上面図イラスト**（`img/t4-top.png`、元絵は機首左向きなので `rotate(theta+90)`） |
| `figDir14(d)` | 14 方向の要素 | 346:148 | **南からの固定視点イラスト**（`img/bi-<id>.jpg`）+ 上/北/東の凡例。ラベル部分は空の色で塗り潰し済み |
| `svgTopDown(theta, phi)` | 画面角, 北角 | 1:1 | （旧）シルエット版。未使用 |
| `svg3D(bank, pitch, front)` | 姿勢, 視点 | 360:250 | （旧）簡易3Dモデル。未使用 |
| `svgAI(bank, pitch)` | 姿勢 | 1:1 | 姿勢指示器。機体シンボル固定、地平線が動く。ピッチ目盛 ±10/20/30、バンク目盛 0/10/20/30/45/60 |
| `svgHI(heading)` | 方位 | 1:1 | 方位指示器。カードが `rotate(−heading)`、N/3/6/E/… の表記 |
| `svgCockpit(bank, pitch, yaw, progress)` | 姿勢+ヨー+前進度 | 3:2 | 風防クリップ内に空・地面・水平線・目印（太陽、山並み、雪山、塔）、固定 HUD。`progress` 0..1 で目印を最大 1.45 倍に拡大（時間が進むと前進して景色が大きく見える）。出題の①②③は 0 / 0.5 / 1 |

3D モデルの視点: 後方は方位角 26°・仰角 18° から見下ろす。前方視点は機体を 180° ヨーさせて同じカメラで描く。

## 6. 状態と永続化

```
state = { mode, question, qcount, answered, t0 }
settings = { north, ops, init, auto, qLimit: 秒(0=なし), sLimit: 秒(0=なし), qCount: 問(0=なし), dirLabel: kanji|alpha, skipExplain, showIntro, showPractice, theme, version }
hideIntro = { <mode>: true }   // 「次回から表示しない」
stats[mode] = { n, c, t }   // 出題数, 正解数, 合計秒
```

- `localStorage` キー `aat.settings`, `aat.stats`, `aat.mode`。読み書きは try/catch で保護。
- タイマーは出題描画完了で開始、回答確定で停止し、秒を stats に加算。

## 7. 画面遷移と操作

画面は 3 つで、URL のハッシュで切り替える（ブラウザの戻るが効く）。

| ハッシュ | 画面 | 内容 |
|---|---|---|
| `#home`（既定） | ホーム | タイトル「TENRYU」と種目カード 4 枚（種目名のみ: 方位／姿勢指示器／方位×姿勢指示器／操縦操作）。右上のメニュー（ホーム／アプリの説明） |
| `#train/<mode>` | 訓練 | 1 種目 = 1 セッション。種目タブはなく途中で切り替えられない。離れるときは確認ダイアログ。制限時間つき（下記） |
| `#settings` | 設定 | 制限時間（1 問あたり: なし/5〜60 秒、種目全体: なし/1〜15 分）、方位の表記（漢字 / アルファベット）、テーマ、出題設定（北の向き・操作数・初期姿勢・自動で次へ） |
| `#about` | 説明 | 箇条書きで簡潔に: アプリの説明、種目、視点と座標、計器と操作、**3D ビューア**、クレジット |

3D ビューア（`viewer.js`、three.js を CDN の importmap で読み込み、説明画面を開いたときだけ動的 import）:
- モデルは `model/t4.glb`（描画ツールの `?export=1` で FBX から変換。脚・開状態エアブレーキを除去、収納部を機体色で塗り、頂点共有化、テクスチャ 1024px、約 4MB）。
- 世界座標は描画ツールと同じ（x 東・y 北・z 上）。カメラは南 (0,−24,0) から原点。OrbitControls でドラッグ回転・ピンチ拡大、パンは無効。
- 14 方向ボタンで `R = Rz(−h)·Rx(p)` の姿勢へ 0.45 秒で補間。「視点を南に戻す」でカメラを初期位置へ。
- 水平面の格子（z=−6）と東（赤）・北（緑）・上（青）の矢印を表示。
- 画面を離れると描画ループを止め、戻ると再開。読み込み失敗時は文言で通知。

セッションと制限時間:
- 1 問の制限時間があるときはカウントダウン表示（残り 3 秒で赤）。0 になると「時間切れ ✗」として不正解扱いで採点し、正解を強調して解説を出す。
- 種目全体の制限時間があるときは種目バー右に残り時間（残り 30 秒で赤）。0 になると回答中なら即終了、回答済みなら「結果を見る」に切り替わり、成績（出題・正解・正答率・平均解答時間）と「もう一度」「ホームへ」を表示する。
- 既定値（本番はスピード勝負）: アルファベット表記、20 問、1 問 5 秒、全体 5 分、解説スキップ。設定に version を持ち、版が変わったら既定値に戻す。
- 解説スキップ: 計測中は正誤の印を 0.45 秒だけ見せて次へ。練習問題では常に解説を表示。
- 出題数: 10/20/30/50/制限なし。達したら終了して成績を表示。

開始の流れ（`enterMode`）:
1. 操縦操作だけは先に「練習／計測」を選ぶ（`#train/control/practice` | `#train/control/measure`）。
2. 説明画面（種目ごとの箇条書き + 制限時間の要約 + 「次回から表示しない」チェック、既定でオン）。設定「開始時の説明を表示」をオフ→オンにすると再表示。
3. 練習 3 問（制限時間なし・解説あり・記録に含めない。設定で非表示可。操縦操作では出さない）。
4. 計測（制限時間・出題数つき）→ 成績。

操縦操作の「操作ごとの見え方」（`#train/control/gallery`）: 操縦桿（左・右・奥・手前の 1 行、排他）と方向舵（左・右、排他）をボタンで選ぶ。操縦桿は一度に 1 方向しか倒せないので、複合パターンは操縦桿＋方向舵の組み合わせだけ。複数選択時は「同時に行う／順番に行う」を切り替え可。順番に行うときは「操縦桿 → 方向舵」「方向舵 → 操縦桿」で先に行う側を選ぶ（順番で結果が変わるため）。選んだ操作の水平①→②→③を縦に並べて表示し、操作ごとの見え方の説明を添える。目印として雪山の頂と塔の先端にオレンジの輪、①の水平線の位置に破線を描く（`svgCockpit` の第 5 引数 `marks`）。未選択でも水平飛行の 3 枚を出し、条件で出る行は薄くするだけで消さないため、選択しても画面がずれない。さらに選択行と 3 枚を 1 画面に収める（スクロール不要）ため、`body[data-phase="gallery"]` で記録チップ・脇のメモ・冒頭説明を隠し、フレームは風防部分だけ（viewBox 360×188 に差し替え）を `calc((100dvh - 31.5rem)/3)` の高さで表示する。375×667 でも収まることを確認済み。

操縦操作の練習（シミュレータ）: 視界と姿勢指示器を表示し、操縦桿（奥/左/右/手前）と方向舵（左/右）のボタンを押している間だけ姿勢が変わる（バンク 45°/s、ピッチ 18°/s、ヨー 25°/s、上限 ±60/±40/±120°）。SVG の `.ck-att` `.ck-yaw` `.ai-h` `.ai-p` の transform を書き換えて更新する。前進の表現として目印の拡大率を 8 秒周期で 1→1.45 倍に変化させる。

1. ホームで種目を選ぶ → セッション開始 → 新規出題。
2. 回答 → 採点 → フィードバック（正誤、経過秒、解説、正解の強調）→「次の問題」。
3. 設定変更は即座に新規出題。設定「正解したら自動で次へ」が ON なら正解時 1.4 秒後に自動出題。

キーボード: 方位はテンキー 8/9/6/3/2/1/4/7（または w/e/d/c/x/z/a/q）、4択は 1〜4、操縦操作は各区間の 1〜6、Enter で回答/次へ。

## 9. 配信形態: PWA（スマートフォン主体）

主な利用端末はスマートフォン。ホーム画面に追加してアプリとして起動できる PWA として配信する。

| ファイル | 役割 |
|---|---|
| `manifest.webmanifest` | 名称、`display: standalone`、縦向き固定、テーマ色、アイコン 192/512（maskable） |
| `sw.js` | サービスワーカー。初回に全ファイルをキャッシュし、以後はキャッシュ優先でオフライン動作。更新時は `CACHE` の版数を上げる |
| `icons/*.png` | アプリアイコン。現在は仮生成品。正式版は RIKYU AI の納品で置き換える |
| `index.html` の meta | `viewport-fit=cover`、`theme-color`、iOS 用 `apple-mobile-web-app-*` と `apple-touch-icon` |

- Android/Chrome: `beforeinstallprompt` を受けて「ホーム画面に追加」ボタンを表示。
- iOS/Safari: 自動インストール不可のため、共有メニューからの追加手順を案内する。
- 配信は HTTPS の静的ホスティング（GitHub Pages 等）。サービスワーカーは HTTPS か localhost でのみ動く。
- 寸法はすべて `%`・`rem`・`vw`・`fr` で指定し、`px` は使わない。タップ領域は最低 2.75rem。
- セーフエリア（ノッチ）は `env(safe-area-inset-*)` で確保する。

## 10. アイコン（RIKYU AI へ発注する幾何学図形）

## 背景の昼／夜（設定 `scene`）

- 設定 `scene: 'auto' | 'day' | 'night'`（既定 `auto`）。`applyScene()` が `body[data-scene]` を付け、`auto` は判定時刻で 5〜7 時を日の出 `dawn`、7〜17 時を昼 `day`、17〜19 時を夕焼け `dusk`、それ以外を夜 `night` とする（手動は昼／夜のみ）。出題の `render()`、シミュレーター開始、見え方の表示、設定変更時に判定し直す。
- 適用範囲: 姿勢指示器・方位×姿勢指示器の機体画像の背景（`.d14` の `--d14bg`）と、操縦操作の視界 `svgCockpit`（出題・練習・シミュレーター・見え方すべて）。姿勢指示器の計器そのものや方位の上面図は変えない。

## 計測条件は種目ごとに開始前に決める（2026-09-03）

- 設定画面から「計測」群と「説明と練習」群を外し、表示（方位の表記・テーマ・背景）だけにした。`SETTINGS_VERSION` を 3 に上げ、旧版の qCount/qLimit/sLimit は捨てる。

## 解説表示のときの図の大きさと自動スクロール（2026-09-03）

- 解説（`.fb.show`）を出すとき、スマホ幅では 1 画面レイアウトの伸縮を止めて通常の流れに戻すが、図の大きさは変えない。`finish()` が直前に `freezeFigs()` を呼び、`.d14`（機体画像）・`.fig.top`（上面図）・`.frame`（視界 3 枚）の高さを inline の rem で固定する（次の出題で図を作り直すので自然に解除される）。以前は自然サイズに戻していたため、操縦操作の 3 枚が解説で少し拡大していた。
- 解説が出たら `revealFeedback()` が画面のいちばん下まで自動で送る（`scrollTo` の smooth、効かない環境では 400ms 後に即時で送り直す）。利用者が自分でスクロールせずに「次の問題」を押せるようにするため。
- 方位×姿勢指示器の選択肢（`.pair`）が iOS Safari で描画されなかった原因は、幅が確定していなかったこと。外側の `svg` は `width:auto` が 100% と同じ扱いになるため、親の幅が `auto`（縮小して合わせる）だと幅を解決できず 0 になる。対策として親に `width:100%`（PC は 92%）、計器に `width:calc(50% - .125rem); height:auto` と、どちらも確定した幅を与える（高さは縦横比から決まるので `dvh` に頼らない）。

## 操縦操作の 2 操作は「操縦桿 → 方向舵」だけ（2026-09-03）

## 方向舵は機体の上下軸まわり（2026-09-03）

- 方向舵は機体の上下軸まわりに効くので、機体が傾いているときは機首が水平面ではなく斜めに振れる。右バンクで右方向舵なら機首はやや沈む。
- `applyOp`（出題の見え方）: 方向舵の操作は `yaw += r·cos(bank)`、`pitch −= r·sin(bank)`。バンク 0 のときは従来どおり。
- `sim3d.js` の飛行モデル: 方向舵入力を機体軸まわりのヨー角速度 `ry` として扱い、`pitch −= ry·sin(bank)·dt`、`heading += ry·cos(bank)/cos(pitch)·dt`（協調旋回の項はこれまでどおり別に足す）。
- 解説: 傾いた状態で方向舵を踏んだ区間は「景色が流れ、少し上がる（機首が沈む）」のように上下の動きも書き、最後に理由の 1 行を足す。

## シミュレーターの姿勢をクォータニオンに（2026-09-03、v02.02）

- 操縦桿の左右で何回でも回れるように、前後で宙返りができるように、姿勢の持ち方をオイラー角（方位・ピッチ・バンク）からクォータニオン `att` に変えた。オイラー角では真上・真下で破綻するため。角度の上限は設けない。
- 操作は機体の軸まわりの回転として掛ける: 機首軸 +y にロール、翼軸 +x にピッチ、上下軸 +z にヨー（右方向舵は −z 回り）。方向舵が傾きに応じて機首を斜めに振る性質は、この扱いで自然に出る（前の版で入れた cos/sin の補正は不要になった）。
- 協調旋回（バンクによる旋回）は世界の上下軸まわりの回転として掛ける。真上・真下付近（|ピッチ| ≥ 70°）では効かせない。
- 表示と計器のための `st.h` `st.p` `st.b` は毎フレーム `readAttitude()` がクォータニオンから取り出す（機首の向きから方位とピッチ、機体の上と右翼から傾き）。
- 天井 `CEIL` を 1400 m から 3000 m に上げた。60 m/s・ピッチ 25°/s だと宙返りの直径は約 275 m なので余裕がある。地面に着いたときは水平に戻す。
- 三人称のカメラは機体の姿勢に沿って後ろ上から追う（`cam.up` も機体の上向き）。宙返り中も機体を見失わない。

## 編隊飛行とスモーク（2026-09-03、v03）

- **視点**: 一人称 / 三人称（後方）/ 三人称（前方）の 3 つ。前方は機首の 36 m 前・5 m 上から機体を見る。どちらの三人称も機体の姿勢に沿って位置を取り、`cam.up` も機体の上向きにするので宙返り中も破綻しない。
- **編隊** `FORMATIONS`: 単機 / 三角形 / 逆三角形 / 四角形 / 一列縦隊。先頭機（利用者が操縦する機体）から見た 2〜6 番機の位置を [右, 前後, 上] (m) で持つ。一列縦隊は後ろほど低い（先頭が一番上）。
- 編隊機は先頭機の軌跡（`hist`、6 秒ぶん）をたどる。後方距離 ÷ 速度 だけ前の状態を取り、そこに左右・上下の差を足す。旋回や宙返りでも隊形が崩れない。
- 2〜6 番機は GLB を複製して作り、垂直尾翼に番号の板（canvas のテクスチャ、左右 2 枚）を貼る。先頭機はモデルの「1」のまま。
- **スモーク**: 粒（`THREE.Points` と自前のシェーダー）。0.05 秒ごとに機体の 4.2 m 後ろに出し、`SMOKE_LIFE = 29` 秒（宙返り 2 周ぶん）かけて薄れながら広がる。1 機あたり 620 粒。
- 出す機体の決まり: 同じ左右の位置に後続がいる機体は出さない（後ろの機体が煙の中を飛ぶため）。単機なら先頭機が出す。三角形・逆三角形・四角形では 6 番機が先頭の真後ろにいるので先頭機は出さない。一列縦隊では最後尾の 6 番機だけが出す。
- 色は 白・ピンク・緑・黄・青・カラフル（カラフルは 1〜6 番機に別々の色）。
- 画面の操作は視界の下の「編隊」「スモーク（色）」の選択と「スモーク」ボタン。PC はスペースで入り切り。選んだ内容は端末に覚える（`aat.simForm` `aat.simColor` `aat.simSmoke`）。

## 編隊はブルーインパルスの隊形にそろえる（2026-09-03、v03.01）

- 名前と並びの出典: https://wporep.com/blueimpluse/blueimpulse-formation/ の一覧（利用者の指定）。
- 6 機: デルタ（1 番機を先頭に三角）、ピラミッド（上から下へ広がる三角）、フェニックス（1 が頭・4 が尾・2/5 が左翼・3/6 が右翼）、グランドクロス（十字）、ダブルライン（3 機ずつ 2 列）、リーダーズ・ベネフィット（1 番機の後ろに横一列）。
- 5 機: 傘型、カシオペア（W 形）。4 機: ダイヤモンド、アローヘッド、フィンガーチップ。

## 視点の見回しと横画面の操作の置き場（2026-09-03、v03.02）

- 視界をドラッグすると視点が動く（`addLook(dy, dp)`）。一人称はカメラの向きに首振りを掛け、三人称は機体のまわりを回る。上下は ±75° まで。視点（一人称・後方・前方）を切り替えると中央に戻る。画面を 2 回叩く（ダブルクリック）でも戻る。
- PC のマウスは、押しただけなら従来どおり方向舵。6px 以上動かすと方向舵をやめて視点の操作に変わる。
- 煙は時間とともに大きく広がる（粒の大きさ 5 → 60、0.6 乗で早めに太る）。出す間隔は 0.04 秒、1 機あたり 780 粒。
- 横画面では操作を右側にまとめる: 上から 視点ボタン・3 つのボタン・編隊とスモークの選択、右下に方向舵、計器はその左。左側は操縦桿だけにする。
- 縦画面の視界は `min-height:15rem` を入れて小さくなりすぎないようにした。

- オブジェクト（山・民家・木・塔）は `props` の入れ物にまとめ、`setProps(on)` で出し入れする。画面の「オブジェクト あり／なし」で切り替え、`aat.simProps` に覚える。地面の格子・滑走路・壁は残す（位置と高さの手がかりになるため）。

- 視点に「地上」を足した（v03.04）。滑走路の東側 (90, −120, 3) に立ち、機体の方を向く。距離に応じて画角を 11〜55° の間で変える（遠いほど狭く＝望遠のように）ので、離れても編隊とスモークの形が分かる。ドラッグで見る向きを変えられ、2 回叩くと機体の方に戻る。

## シミュレーターの操作の整理（2026-09-03、v03.05）

- 開始前に設定画面（`#setup`）を出し、編隊と地上の目印の有無をそこで選ぶ。「はじめる」で `runSim()` が実際の画面を組む。
- 飛行中の操作は、水平に戻す（アイコン）・スモーク（アイコン、入り切り）・スモークの色（選択）だけ。初期位置のボタンは縦画面のときだけ出す（`.portrait`）。計測へ進むは右のボタン。
- 横画面の置き場: 方位指示器は右上、姿勢指示器は上の中央、視点ボタンは下の中央、スモークなどのアイコンは右下（方向舵の上）、操縦桿は左下、読み取り値は左上。
- 画面を 2 回叩くと視点が正面に戻る（指でも判定する）。横画面で左上（ホームボタンのあたり）を叩くと「戻るには縦画面にしてください」と出す。
- 着地したら、その時の姿勢のまま動きを止める（`st.ground` が立つ間は `step` を飛ばす）。「水平に戻す」か「初期位置」で再開する。
- 追従機の尾翼の番号がずれていたのを直した。モデルの複製は元と同じ平行移動を持っているのに、入れ物にも同じ平行移動を掛けていたため、板だけが機体から離れていた。板は平行移動を掛けた別の入れ物に入れる。

- 縦画面は試験対策のシミュレーターとして簡素にする（利用者の指示）。スモークの入り切りと色、前方・地上の視点は横画面のときだけ出す。編隊と地上の目印は開始前の設定画面で選ぶ（縦でも選べるが、遊びの操作は横画面）。

- 編隊は飛びながら変えられる（横画面のアイコン）。アイコンは隊形を点で表した図で、`FORMATIONS[k].offs` から自動で作る（先頭機は橙、上下の広がりが大きい隊形は横から見た図にする）。
- 合流と離脱はなめらかにする: 各機は `join`（0〜1）を持ち、`ENTRY`（先頭機の後ろ 300〜520 m、左右と上下にずらした位置）と所定の位置の間を 4 秒かけて行き来する。`join` が 1 に近いときだけスモークを出す。軌跡は 12 秒ぶん残して、合流位置からでも先頭の航跡をたどれるようにした。

- 尾翼の番号の位置は決め打ちをやめ、読み込んだモデルから実測する（`measureFin`）。「後ろ寄り（前後で後ろ 42% より後ろ）・高い（高さの上 28%）・左右に薄い（全長の 6% 以内）」頂点を集めて囲む箱を作り、その左右の面に番号の板を貼る。板の大きさは箱の短い辺の 62%。モデルを書き出し直しても位置がずれない。

- 横画面の操縦桿は左下の角から少し離す（`.stkwrap` に左 2.25rem・下 1.75rem の余白）。角に寄りすぎると親指が窮屈で、端末の縁にも当たるため。

## 自動操縦（2026-09-03、v03.09）

- 地上から編隊の演技を見るための自動操縦。横画面のアイコンで入り切りする（押すと地上の視点に切り替わる）。入れている間は操縦桿と方向舵の操作は効かない（薄く表示する）。
- 動きは 3 つの繰り返し: 周回（観覧位置のまわり半径 430 m、高度 170 m、22 秒）→ 正面通過（観覧位置の向こう 700 m をねらって通り抜ける、15 秒）→ 宙返り（1 周ぶん、最大 18 秒）。
- 操縦は目標点への追尾: 方位のずれをバンクの目標に（±52°）、高さのずれをピッチの目標に（±16°）変え、それぞれの差から操縦桿の入力を作る。飛行モデルは手で操縦するときと同じものを通すので、編隊も煙も同じように付いてくる。
- 入れたときは観覧位置の南西の空（約 700 m）から演技を始める。

- 地上視点の作り直し（v03.10）: 機体を追いかけない。向きは `gYaw` `gPitch`（自分で決めた方向）＋見回しのドラッグだけで変わる。画角は 42° に固定（距離で寄せるのはやめた。追ってしまって見にくいため）。
- 目の高さは 1.6 m（人の背丈）。立ち位置 `gEye` は 2 回叩いた場所へ移す（`groundMoveTo`）。画面の座標から光線を飛ばし、地面・滑走路・オブジェクト（山・家・木・塔）に当たった点の 1.6 m 上に立つ。当たらなければ「その場所には立てません」と出す。
- 地上視点に入ったときと、立ち位置を移したときだけ、機体の方へ一度向ける（それ以外では自動で動かない）。

- 隊形の変更はすべてなめらかに（v03.11）。各機は「いまの位置」`cur` を持ち、毎フレーム目標の位置へ指数で寄る（時定数 1.4 秒、約 4 秒でほぼ所定の位置）。隊形から外れる機体は `ENTRY`（後ろの遠く）へ向かい、そこへ届いたら消える。目標に落ち着くまでスモークは出さない。機数が変わらない隊形どうしの変更でも、機体が新しい位置へ動いていく。

## 自動操縦の演目（2026-09-03、v03.12）

- 演目は `PROGRAM` の順に繰り返す: 旋回 → 正面通過 → デルタ・ループ → 旋回 → デルタ・ロール → 正面通過 → ハーフ・スロー・ロール → 旋回 → レター・エイト → 正面通過 → バーティカル・クライム・ロール → 旋回 → コークスクリュー → 旋回 → チェンジオーバー・ターン → 空中開花 → レインフォール。名前の出典はブルーインパルスの課目一覧（masdf.com）。
- 機体は 1 機を操縦して編隊が付いてくる作りなので、機体ごとに別々に動く課目（交差・対向）は隊形の変化で表す（チェンジオーバー・ターンは旋回中に一列縦隊へ、空中開花は横一列へ、レインフォールはピラミッドへ）。課目が終わると利用者が選んでいた隊形に戻す。
- 課目ごとの操作: 宙返り＝引きっぱなし 1 周、横転＝右へ 1 周（機首は少し上げ）、半横転＝背面で少し飛んでから戻す、8 の字＝右 1 周・左 1 周、垂直上昇＝引いて 70° 超えたら横転して押し戻す、らせん＝上げながら回り続ける。
- どの課目でも最後に安全の補正を掛ける（110 m より低ければ上げ、1500 m より高ければ下げ）。
- 自動操縦の間は、操縦桿の傾けぐあいが視点の移動になる（機体の操作はしない）。方向舵は隠す。演目の名前を視界の下に出す。

- 演目は実際の課目の説明（masdf.com の各課目のページ）に合わせた（v03.13）。隊形の広がり `formScale` を足し、課目の中で間隔を変える。
  - チェンジオーバー・ターン: 縦隊で入り、正面でデルタに組み替えて大きく旋回。旋回しながら間隔を詰める（1.9 → 1.0）。
  - ワイド・トゥ・デルタ・ループ: 間隔の広いデルタ（2.4 倍）で入り、輪を描きながら詰める。
  - 上向き空中開花: 正面で垂直上昇し、横一列へ大きく開く（3.2 倍）。
  - レインフォール: 輪に入り、機首が真下を向いたあたりでピラミッドへ大きく散開（2.6 倍）。
  - 360 度ターン & ループ: 1 周旋回してから宙返り。

- 技を 1 つだけ出す（v03.14）。横画面の「技」のボタンから課目を選ぶと、その課目の間だけ自動操縦になり（`runManeuver`）、終わると操縦が戻る（`oneShot`）。移動のための旋回と正面通過は一覧に出さない。
- 自動操縦の間も視点は自由に切り替えられる（一人称・後方・前方・地上）。自動操縦のときは操縦桿が視点の移動になり、方向舵は隠れる。

- 返信は 2 か所へ届く。(1) 投稿した端末のアプリの中（合言葉で読む）。(2) メールアドレスを書いてくれた人にはメール（Edge Function `feedback-reply` が Resend で送る。置いていなければアプリの中だけ）。
- 通信は `feedback.js`（Supabase の REST を直接たたく。SDK もビルドも使わない）。`SUPA_URL` / `SUPA_KEY` が空のあいだは、これまでどおりメールの下書きを開く形で動く（`CONFIGURED`）。
- データベースは `dev/docs/feedback/feedback.sql`。表は利用者に見せず（`revoke all ... from anon`）、触れる口は `SECURITY DEFINER` の関数 3 本だけ。
  - `submit_feedback` 送る（本文・名前・メール・添付の形式と大きさをサーバー側でも確かめ、10 分 50 件のあふれ止め）。合言葉を返す。
  - `get_feedback_by_tokens` 自分の投稿と返信を読む（合言葉に一致する行だけ、最大 50）。
  - `mark_feedback_read` 「読んだ」を記録する唯一の経路。
- 指示書に沿った点:
  - 時刻の列を 3 つ持つ（`replied_at` / `admin_read_at` / `user_read_at`）。返信のあとに再返信しても印が付け直せる。
  - 利用者側の印は `max(replied_at, admin_read_at) > user_read_at`、管理者側は `admin_read_at` が空か `created_at` より古いとき。読んだだけでも印が付く。
  - 印を消すのは画面を開いた瞬間。既読の書き込みは関数 1 本だけを通す。失敗しても画面は壊さない。
  - 添付は表示する側でも `data:` の形を確かめてからリンクにする。合わなければ「開けません（形式が不正です）」と出し、中身は残す。
  - 利用者に見せる文は「返信あり」「読みました」「まだ確認していません」の 3 通りを別々に用意する。
  - 本文・名前・メール・ファイル名は、画面に出すときすべて escape する。
  - 管理者の判定は、画面側はメールの SHA-256（目隠し）。本当の権限は RLS（`is_feedback_admin()`）。
  - メールアドレスがない投稿は、受信箱に「（メールなし）」と出し、返信はアプリの中だけに届くと書く。
- 確かめ方: `dev/docs/feedback/セットアップ.md` の「確かめること」。表示側の濾しと escape は、作り物の行を差し込んだ画面で確認済み（許していない data URI はリンクにならない、`<script>` は文字として出る）。
- 利用者の作業: セットアップ.md の 1〜4（5 は任意）。

## 自動操縦: 進入・機数・墜落防止（2026-09-03、v03.17）

- **墜落しない**。高さだけで判断すると、低い正面通過（130 m）で引き起こしてしまい、背面のときは引くほど地面に向かう。そこで `safety()` は
  (1) 低くて背面気味（`|bank|>60` かつ `z<220`）なら **まず翼を水平に戻す**、(2) `z + fwd.z*SPEED*6`（6 秒先の高さ）が 120 m を切るか `z<80` なら水平にして引き起こす、の順で効かせる。
  最後の砦として `step()` で、自動操縦中は `z<45` にならない（下回ったら水平に戻す）。自分で操縦しているときは、これまでどおり地面で止まる。
- **技ごとに機数が集まる**。`PROGRAM` の各課目に `form` を持たせ、`beginManeuver()` が いまの隊形によらずその隊形にする（コークスクリューとバーティカル・クライム・ロールは 2 機、レター・エイトとハーフ・スロー・ロールは 4 機、ほかは 6 機）。課目が終われば利用者の選んだ隊形（`userForm`）に戻る。合流は `placeMates` がなめらかに行う。
  隊形に `pair`（2 機）と `trail`（縦隊）を追加。`trail` は チェンジオーバー・ターンが `'line'` という**存在しない名前**を指していた不具合の修正でもある（毎フレーム例外になり、画面が止まって見えていた）。
- **見ている前方で行う**。`eyeDir()` が地上視点の向き（`gYaw - look.y`）を返す。`planEntry()` はその正面 520 m を中心に、機体に近いほうの横 400 m に「門」を置き、`in`（門へ）→ `align`（正面の中心へ）→ `do`（技）の順に進む。旋回だけは `front:false` で、これまでどおり移動に使う。
  進入の途中で見ている向きが 35°より大きく変わったら、進入路を引き直す。
  回る課目（レター・エイト、チェンジオーバー・ターン、コークスクリュー、360 度ターン & ループ）は、`turnSign` で **観覧位置から遠ざかる側へ回る**（近づく側へ回ると頭上を越えて後ろへ抜ける）。
- **どこから来るか分かるようにする**。進入のあいだ `st.cue` に「右手（東）から進入」のように出し（画面の課目名の右に「｜」で続ける）、門の位置に高さ 320 m の柱を立てる（地上視点のときだけ見せる）。
- 自分で操縦していて技を 1 つ選んだときは、地上視点なら進入から、それ以外の視点ならその場で始める（高さが足りなければ `climb` で上げてから）。終わりに `out` で水平に戻してから操縦を返す。
- 確かめ方（`scratchpad/h39/autocheck*.html`、`step()` を直接回す作り）: 通しの演技 900 秒で 地面に着かず 最低高度 143 m、各課目の 74〜100% の時間が視界の正面 70°以内。すべての技を 自分で操縦している状態から 1 つずつ試して、地面に着かず 19〜73 秒で 水平の姿勢で操縦が戻る。

## メニューの折り返し（2026-09-03、v03.18）

- メニュー（`.menulist`）は絶対配置で、置ける幅の元になるのはメニューボタンの幅しかない。そのため幅は `min-width` でしか決まらず、11rem では「ご要望・お問い合わせ」＋赤い印が入らず 2 行に折り返されていた。`min-width` を 13.5rem にし、項目は `white-space:nowrap` にした（360 px の画面でも横にはみ出さないことを実測）。
- お問い合わせの説明文は、原稿の途中で改行していたぶんが画面で余計な空きになっていたので 1 行にまとめた。長い英数字の貼り付けで枠が横に伸びないよう、投稿と返信の本文に `overflow-wrap:anywhere` を入れた。

## 横画面をタブレットでも・近くを飛ぶ演技・画面の拡大（2026-09-03、v03.19）

- **横画面の作りがタブレットで出なかった**。条件が `(orientation:landscape) and (max-height:34rem)` で、タブレットの横（高さ 48〜52rem）は外れていた。条件を `(orientation:landscape) and (max-height:34rem),(orientation:landscape) and (pointer:coarse)` に変える（指で触る画面の横向きなら背が高くても使う）。パソコンは `pointer:fine` なので これまでどおり。CSS 2 か所と JS の `matchMedia` の 3 か所を同じ条件にすること。中の寸法は clamp で書いてあるので、背の高い横画面でも崩れない。
- **演技が遠かった**ので近づけた。`SHOW` の `GATE` 520→300、`SIDE` 400→220、`R` 430→330、`ALT` 170→150。各課目の高さも 2〜3 割 下げた。回る課目は傾きを深くして輪を小さくした（レター・エイト 44→56°、360 度ターン 46→54°、チェンジオーバー 45→52°。輪の半径 = v²/(g·tanφ) なので、56°なら 250 m ほど）。観覧位置からの距離は p90 で 971→823 m、正面 70°以内に入る時間は 88%。
- **頭上通過**（`byover`）を追加。観覧位置の 600 m 向こうを狙って低く（120〜130 m）飛び、通り過ぎたら終わる。低く飛ぶので、地面の備えは「6 秒先の高さが 90 m を切るか、いま 70 m を切るか」に下げた（前は 120/80 で、低い通過のたびに引き起こしていた）。
- **画面の拡大**。`cam.fov = 視点ごとの画角 ÷ 倍率`（`setZoom` / `zoomVal`、1〜6 倍）。2 本の指の間隔で倍率を決める（`sim.pts` に触れている指を持ち、2 本以上なら見回しをやめて拡大に切り替える）。パソコンは Ctrl + ホイール（ホイールだけは操縦桿の前後のまま）。右上に倍率を出し、押すと等倍。視点を変えたときも等倍に戻す。
- 技の一覧は同じ id を 1 つにまとめる（頭上通過と正面通過が演技の中に何度も出るため）。

## スモーク・正面からの進入・視点の自動追従（2026-09-03、v03.20）

- **スモークが細かった**。太さは `gl_PointSize = 太さ × (240 ÷ 距離)` で、物理どおりに書くと遠くでは 1〜2 画素になり見えない。出た直後の太さを 5→6、広がりの効き方を `age^0.6 × 55` から `age^0.5 × 60` に変え、**最小 3 画素・最大 90 画素** の頭打ちを入れた。最小で遠くの演技でも筋が見え、最大で真後ろから見たときに画面を覆わない（上限なしで太さだけ上げると、三人称視点で真っ白になる）。濃さは 1 粒 0.4（重なって濃く見える）。消え方は `(1-age)^1.5`。
- **迫力のある技は正面から**。`PROGRAM` に `entry:'front'` を持たせ、`planEntry()` が門を「正面の 1060 m 先」に置く。そこからまっすぐ向かってきて、技は正面で始まり頭の上へ抜ける。付けたのは 頭上通過・デルタ・ループ・コークスクリュー・バーティカル・クライム・ロール・上向き空中開花・レインフォール。ほかは これまでどおり横から入って正面を横切る。コークスクリューは登りの角度を 22°→16° にして、前へ進む力を残した（真上に上がると頭上を通り過ぎない）。
- **視点の自動追従**（`setFollow` / `followState`、横画面のアイコン `#simFollow`、`aat.simFollow` に記憶）。地上から見るとき、機体の方へ 0.45 秒の時定数で首を回す。切ってあれば これまでどおり自分で向けた方向のまま。入れているあいだは進入の目印（柱）を出さない。実測: 切だと視線と機体のずれは最大 180°、入だと平均 2°・最大 40°。
- **横画面の右に「解き方のメモ」が出ていた**。幅 64rem 以上で `.layout` が 2 段組みになるため、タブレットの横画面で出ていた。`body[data-phase="sim"]` のときは `.card.side` を出さず、1 段組みにする。

## キューピッド・スタークロス・自然な合流（2026-09-03、v03.22）

- **コーク・スクリューの作り直し**。1 機がまっすぐ水平に進み、2 番機がその周りを半径 26 m・1 周 3.6 秒で回る。背中（機体の上）を輪の中心へ向けるため、機体の軸まわりに θ+180° 回した姿勢を与える（実測: 上向きベクトルと中心方向の内積 0.93 ＝ 26/27.8 で、幾何のとおり）。実際の演技では直進する 5 番機が背面で飛ぶ（説明文に添えた）。
- **終わりの判定の符号**。`(機体 − 目)·視線` は「手前が正、越えると負」。`> 300` としていたため、頭上通過とコーク・スクリューが始まった瞬間に終わっていた。`< −300` に直した。
- **描き物の課目**（キューピッド・スタークロス）。編隊の位置合わせでは描けないので、観覧位置の正面の空に面を立て、その上の式のとおりに機体を置く。1 番機（操作する機体）は隠し、2 番機以降で描く（キューピッド 3 機、スタークロス 5 機）。
  - キューピッド: 2 機が中央を上がってから左右のハートの葉を回り、下の尖りで合わさる（`16 sin³t` と `13cos t − 5cos2t − 2cos3t − cos4t` の心臓形）。3 機目が左下から右上へ貫く。
  - スタークロス: 5 機が中心から 5 方向へ開き（花）、そのあと 1 つ飛ばしの頂点へ渡って星形（五芒星）を描く。
  - 姿勢は道の接線を機首、図の中心の側を機体の上に向ける。図に入る前に編隊が組み終わるのを待ち（`matesReady`）、6 秒かけて隊形の位置から図の始点へ寄せる。終わったら、そのときの位置から隊形へ戻す（`endFigure`）。地面より下に来ないよう、図の面の高さと大きさを取ってある（実測の最低高度 182〜239 m）。
- **合流・離脱を自然に**。時定数の指数寄せ（始めが速い）をやめ、14 秒かけて「ゆっくり出て ゆっくり入る」曲線で寄せる。まっすぐ最短で寄らないよう、道のりの 28%（最大 90 m）だけ外へ膨らませる（`startJoin`）。離れる機体は後ろの遠く（620〜960 m）まで下がりきってから消す。
- **頭上を抜けたあとは、いったん離れる**。移動の旋回（`orbit`）の隊形を `solo` にしたので、通過のあと後方で隊形が解け、次の課目までに組み直す。
- **課目の説明**。`PROGRAM` の各課目に `desc` を持たせ、課目が変わったら画面の下に 9 秒出す（`#trickDesc`）。名前と中身は 航空自衛隊の展示飛行の課目紹介と、一般の解説記事を参照した。

## 地上での操作・方位計・正面から入る課目（2026-09-03、v03.23）

- **指を離してもスティックが戻っていなかった**。`sim.stickVec` を離したときに 0 にしていなかったので、自動操縦のあいだ 視点が回り続けていた。
- **地上＋自動操縦のスティックは立ち位置を動かす**（`groundWalk`）。見ている向きを前として前後左右へ 34 m/s。高さは 地面と滑走路への真下向きの当たり判定で決める（山や家には登らない。オブジェクトの上に立つのは、これまでどおり画面を 2 回叩いたとき）。三人称・一人称のときは これまでどおり見回しに使う。スティックの絵は自動操縦のとき丸いつまみにし、見出しを「視点の移動」、目印を 前／後ろ／左／右 に変える。
- **右上の方位計**は、地上から見ているときは「自分が見ている方位」（`st.gh` = `gYaw − look.y`）。ほかの視点では これまでどおり機体の方位。
- **正面から入る課目が、正面から外れていた**。門を正面の線の上に置くと、門で 180 度 向き直すことになり、旋回のふくらみのぶん横へずれる。門を正面の線から 420 m 横・1200 m 先に置き、そこから正面の線に乗り直させる。始める条件も「横のずれ 90 m 以内・向きのずれ 10 度以内・観覧位置の 780 m 手前」にした。コーク・スクリューの 1 番機は、傾き ±16 度までで向きを直す。実測: コーク・スクリューと頭上通過は観覧位置の 21〜22 m のところを通る（前は 187〜249 m 横）。
- **編隊が空中で止まって見えた**。理由は 2 つ。
  1. 後ろへ下がる速さが飛ぶ速さと釣り合うと、世界の中では止まって見える。前後のずれの変化に 30 m/s の上限をかけた（横と上下は速くてよい）。離れる機体は 520 m まで離れたら消す。
  2. 記録した経路より前の位置を求められると、いちばん古い記録の点に貼り付いていた。古い点から後ろへ まっすぐ延ばして置くようにした（`stateAt` の外挿）。
  図を描く課目に入るときも、寄せ元を「編隊で飛び続けていたらいる位置」にして、止まって見えないようにした。
