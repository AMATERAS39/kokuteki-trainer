01 — PRINCIPLES

設計の芯

個々の値より先に、この 5 つを決めておくと迷わなくなります。

1. 計器の世界から色と書体を取る

題材は航空機の計器です。だから地は黒に近い紺（#0b1017）、線は白の半透明、数字とラベルは等幅。 導線に使う青緑（#5ad1e6）は計器の目盛りの色、強調の橙（#ffb020）は警告灯の色から取っています。 題材の中にある色を使うと、飾りではなく必然に見えます。

2. 強い色は 1 ページに 1 系統だけ

橙は「数字」と「主要ボタン」だけに使い、それ以外は青緑と灰で通します。 強い色を 2 つ同じ強さで置くと、どちらも効かなくなります。

3. 寸法は px で置かない

すべて rem・%・vw・clamp。画面幅で伸縮し、端末の文字サイズ設定にも追従します。 ブレークポイントも rem で置きます（@media (min-width:48rem)）。

4. 動かすのは CSS、JS は印を付けるだけ

現れ方は CSS の遷移に任せ、JS は「画面に入った」という class を付け外しするだけにします。 毎コマ JS で opacity や transform を書くと、指の動きは合成側で進むので必ず遅れ、がたつきます。

5. 図はアプリが実際に描いている部品を出す

案内ページのカードに出ている計器の絵は、スクリーンショットではなくアプリ本体の描画関数（engine.js）を そのまま読み込んで描いています。説明と実物がずれないのが利点で、読み込めなかったときは図の枠ごと消して文章だけにします。

02 — COLOR

色

面は 3 段、文字は 4 段、差し色は 2 つ。線は色ではなく白の半透明で置きます。

--bg #0b1017地。いちばん奥

--panel #0f1620カード・帯・表の面

--panel2 #141a1c強調カードのグラデの上端

--text #e8eef5本文

--soft #a9b8c8カードの中の説明

--muted #93a3b5補足・リード文

--faint #6f8090ラベル・注記

--cyan #5ad1e6導線・小見出し・リンク

--amber #ffb020数字・主要ボタン

線は 3 段の半透明で持つ

名前値使いどころ
--linergba(255,255,255,.08)面の区切り。節と節、カードの枠
--line2rgba(255,255,255,.16)入力欄・副ボタンの枠（少し強い）
--dashrgba(255,255,255,.12)カードの中の破線の仕切り

半透明にしておくと、地の上でもカードの上でも同じ 1 本で通ります。面ごとに線の色を作る必要がありません。

透過の差し色

青緑と橙は、そのままではなく薄めて面にも使います。 rgba(90,209,230,.1) は帯のボタンの下地、.12 は記号の下地、.35〜.6 は枠。 橙は rgba(255,176,32,.28) で有料プランのカードの枠、.32 で押したときの影に使います。

面の重ね方

見出しの舞台だけは、単色ではなく放射のグラデーションを 2 枚重ねています。 右上に青緑、左下に橙を、どちらも 8〜12% の薄さで置き、その上に暗い縦のグラデーションを敷きます。

background:
  radial-gradient(120% 90% at 78% 8%,  rgba(90,209,230,.12), transparent 62%),
  radial-gradient(90% 70% at 20% 60%,  rgba(255,176,32,.08), transparent 62%),
  linear-gradient(#0d141d, #0b1017);

04 — LAYOUT

寸法とレイアウト

変数値役割
--wrap70rem本文の最大幅。中央寄せの共通の器
--padclamp(.875rem,3vw,1.375rem)左右の余白。全部ここから取る
--secclamp(2.5rem,6vw,4rem)節の上下。節の区切りは 1px の線だけ

並べ方は 3 通りだけ

  • 自動で折り返す格子 — repeat(auto-fit,minmax(min(17.5rem,100%),1fr))。 min(…,100%) を挟むのが要点で、これがないと狭い画面ではみ出す。
  • 2 分割 — 1fr から @media (min-width:48rem) で 1.15fr .85fr へ。
  • 表 — grid-template-columns:1.6fr .8fr .7fr .7fr。狭い画面では比率だけ変えて、崩さない。

ブレークポイント

34rem・40rem・48rem・52rem・56rem。すべて rem なので、端末の文字サイズを大きくしている人には、 その人にとっての「狭い画面」で切り替わります。px で置くとこれができません。

上の帯

position:sticky + backdrop-filter:blur(.875rem) + 82% の不透明度。 中のリンクは flex の nowrap で 1 行に固定し、入りきらない幅では overflow-x:auto で横に送ります（スクロールバーは隠す）。縦に折り返させないのが決めです。

05 — REVEAL

現れ方

この意匠のいちばんの特徴です。節の中身が、画面の下から入るあいだに出来上がり、 上へ巻き戻すとそのぶん戻ります。動きは 4 種類だけ。

MOTION SAMPLE
up浮かび上がる — 見出し・段落・札。既定はこれ
l左から — カード（奇数番）・用語・質問
r右から — カード（偶数番）
wipe左から右へ拭う — 表の行（clip-path）
--i:4遅れは 95 ミリ秒ずつ。7 番目で頭打ち
項目値意図
時間1.15s長め。ゆっくり出るほど「効果」ではなく「佇まい」に見える
加減速cubic-bezier(.16,1,.3,1)最初に速く、終わりで長く伸びる。止まり際が静か
ずらし--i × 95ms並びの順に 1 つずつ遅らせる
ずらしの上限78 番目以降は待たせない（下のほうが遅すぎるのを防ぐ）
移動量2.25〜2.75remup は同時に scale .985。近づいてくる感じが出る
出す線画面の下から 88%下端より少し内側で出し始める
戻す線画面の下から 96%出す線とずらす（同じだと境界で小刻みに点滅する）

順番の決め方

--i は 並びの順（文書の順）で振ります。選び手（.card → .tile → h2 …）の順で振ると、 札が見出しより先に出るなど、ばらばらに見えます。集めたあとに compareDocumentPosition で並べ替えてから振ります。

カードの左右交互は、カードだけを数える別のカウンタで決めます。並びの順の番号（偶奇）で決めると、 カードが偶数番ばかりに当たって全部が同じ側から入ります。

JS の役割は 3 つだけ

  • 読み込み時に .an と種類（up / l / r / wipe）と --i を付ける。
  • スクロールのたびに位置を見て .on を付け外しする。
  • 動いているあいだだけ .mv（＝will-change）を付け、2 秒で外す。

06 — AMBIENT

常に動いているもの

見出しの舞台にだけ置きます。どれも非常に遅いのが決めで、 速い動きは 1 つもありません。目に留まらない速さだから、うるさくなりません。

入場（読み込んだ直後の一度きり）

見出しの中身だけは、スクロールを待たずに順に入ります。 ワードマークが左から（inL .9s .05s）、副題が左から（.18s）、リード文が下から（rise .9s .32s）、 ボタン（.46s）、数字の帯（.58s）。機体の絵だけは右上から回り込んで入ります（inR 1.3s .25s）。

遅らせる幅は 0.05 秒から 0.58 秒。この 半秒ほどの中に全部を収めるのが、待たされずに順序が見える上限です。

触ったときの反応

押せるものは、必ず「浮く」か「沈む」。色だけを変えるのはやめています。

対象変化備考

副ボタン hoverborder → 青緑 60%＋ 下地に青緑 8%、同じく −.19rem

現れ方は 1.15 秒、触った反応は 0.2〜0.35 秒。「読むための動き」は遅く、「操作の返事」は速くと分けています。

開閉（つまずきの箱）

max-height:0 → 18rem を .35s ease で。記号は ＋ と − を差し替えるだけ。 高さを auto にできないので上限を決め打ちしますが、中身が短いので不自然になりません。

08 — REDUCED MOTION

「視覚効果を減らす」への向き合い方

ここは普通と違う判断をしています。動きを消さず、動きの性質を変えます。

現れ方まで消すと、この設定の人だけ「何も出てこないページ」になり、内容が伝わりません。 そこで、出ること自体は残し、次のように置き換えます。

ふつう減らす設定理由
移動・拡大・切り出し濃さの変化だけ版組みも塗り直しも起きない。いちばん軽い
1.15 秒0.6 秒待たせない
ずらし 95ms55ms順序は残す

常に動く飾り全部止める読む邪魔になるものから消す
will-changeopacity だけ層を抱えない

09 — SCROLL

スクロールまわりの作法

読み進み具合の線

画面の最上部に 0.125rem の線を固定し、青緑から橙へのグラデーションで幅を伸ばします。 scrollTop / (scrollHeight − clientHeight) の百分率を width に入れるだけ。

いま見ている節を光らせる

画面の高さの 30% の線を基準に、その線を越えた最後の節を「いま」とします。 節の位置は毎回引き直さず、現れ方の見回りと同じ拍で見ます（別々に走らせると、巻くたびに版組みが 2 回起きます）。

更新したら元の場所へ戻す

これがいちばん厄介でした。効いた形はこうです。

  • history.scrollRestoration='manual' にして、ブラウザ任せをやめる。
  • 位置は 動かすたびに sessionStorage へ控える（350ms の間引き付き）。 pagehide だけに頼ると、来ない画面がある。
  • 戻すのは hash が一致したときだけ。URL に節の名前が残っているとブラウザがそこへ飛ばすため。
  • 戻すときは scroll-behavior を一時的に auto にして一足飛びに置く。 なめらかに戻すと、途中で指が触れて止まり、節の切れ目に置き去りになる。
  • 絵が入ると背が伸びるので、60 / 200 / 600 / 1200 / 2000 ミリ秒で置き直す。 ただし利用者が自分で動かしたら（wheel / touchstart / keydown / pointerdown）そこでやめる。
  • 巻いているのが html か body かは置かれ方で変わるので、両方見て大きいほうを取る。

見回りの拍

scroll は requestAnimationFrame で 1 コマ 1 回に間引き、 さらに 400ms ごとの見回りも回します。入れ物側が巻いていて scroll が飛んでこない置かれ方でも、 位置で判じているので必ず出ます。白紙のまま止まる事故の備えにもなります。

矩形は 先に全部読んでから、そのあとで class を付けます。読みと書きを交互にすると、その回数だけ版組みが起きます。

10 — PITFALLS

落とし穴

どれも実際に踏んで、直したものです。他のサイトでも同じ形で出ます。

横を overflow-x:hidden で切ると、指が一瞬止まる

hidden は body 自身を巻き取り箱にしてしまい、横へずらす動きのたびに「どちらへ巻くか」の取り合いが起きます。

直しoverflow-x:clip を使う。clip は巻き取り箱を作りません。ただし html が visible のときは body に効かないので、内側の器（main）に掛けます。

animation-timeline: view() を当てにしない

iPad の Safari は「使える」と答えるのに animation-range が効かず、画面から上へ抜けるまで出来上がりませんでした。表の最後の行が半分で止まって見えます。

直し自前の位置判定 ＋ CSS の遷移に戻す。使えるかどうかを聞いて分岐するのではなく、使わないと決める。

毎コマ JS で opacity や transform を書かない

指の動きは合成側で進むので、JS の書き込みは必ず遅れます。端末によってはがたつきます。

直しJS は class の付け外しだけ。動かすのは CSS の遷移に任せる。

will-change を付けっぱなしにしない

60 個を超える要素に付けたままにすると、その数だけ層を抱えてかえって重くなります。

直し動き始めに付け、2 秒後に外す（.mv のような一時的な class で）。

同じ重みの指定を、別の塊で二度書かない

@media の中に .an.wipe{opacity:0} と書いたところ、塊の外の .an.on{opacity:1} が打ち消され、表が永久に出なくなりました。

直し打ち消される側の値は、同じ塊の中で書き直す。

overflow のある箱の中身を、縦にずらす動きで出さない

箱からはみ出したぶんが切り落とされ、下のほうの要素が欠けます。

直し中身ではなく箱ごと動かす。

出る順は「集めた順」ではなく「並びの順」

選び手の並びで番号を振ると、札が見出しより先に出るなど、ばらばらに見えます。

直し集めたあとに compareDocumentPosition で並べ替えてから振る。

左右交互は、全体の番号の偶奇で決めない

並びの順の番号で決めると、カードが偶数番ばかりに当たって全部が同じ側から入ります。

直し交互にしたいものだけを数える、専用のカウンタを持つ。

scroll-behavior:smooth と位置の復元は相性が悪い

なめらかに戻している途中で指が触れると止まり、中途半端な場所に置き去りになります。

直し戻す瞬間だけ auto に切り替え、終わったら元に戻す。

画像で背が伸びるので、復元は一度では足りない

読み込み直後は紙が短く、控えた位置まで戻れません。

直し数百ミリ秒おきに数回やり直す。ただし利用者が自分で動かしたら即やめる。

CSS の塊を丸ごと差し替えるときは、消える class を数える

置き換えで .btn の定義ごと落としたことがあります。

直しHTML の class="…" を全部集め、<style> の中に定義があるかを突き合わせる短い処理を回す。

検索結果の印（favicon）は 48 の倍数だけを出す

64×64 を混ぜていたため、Google に使われていませんでした。中身だけ差し替えても、住所が同じだと古い印が出続けます。

直し96 と 192 だけにする。/favicon.ico も置く。描き直したら住所に ?v=2 を付けて取り直させる。

11 — SKELETON

そのまま持ち出せる骨格

現れ方の仕掛けは、この 2 つだけで動きます。

CSS

/* 動かすのは CSS。JS は .on を付け外しするだけ */
.an{opacity:0;transition:opacity 1.15s cubic-bezier(.16,1,.3,1),
                    transform 1.15s cubic-bezier(.16,1,.3,1),
                    clip-path 1.15s cubic-bezier(.16,1,.3,1)}
.an.up  {transform:translateY(2.25rem) scale(.985)}
.an.l   {transform:translateX(-2.75rem)}
.an.r   {transform:translateX(2.75rem)}
.an.wipe{opacity:1;clip-path:inset(0 100% 0 0)}
.an.on  {opacity:1;transform:none;clip-path:inset(0 0 0 0);
           transition-delay:calc(var(--i,0) * 95ms)}
.an.mv  {will-change:opacity,transform}   /* 動いている 2 秒だけ */

main{overflow-x:clip}                     /* hidden ではなく clip */

@media (prefers-reduced-motion:reduce){
  /* 消さない。性質を変える */
  .an,.an.up,.an.l,.an.r{transform:none;transition:opacity .6s ease}
  .an.wipe{opacity:0;clip-path:none;transition:opacity .6s ease}
  .an.on{opacity:1;transform:none;clip-path:none;
         transition-delay:calc(var(--i,0) * 55ms)}
}

JS

/* 1. 印を付ける（並びの順に --i、カードだけ左右交互） */
var prep=function(sec){
  var groups=['.card','.tile','.tr','.qa','h2','.lead'];   // 動かしたいもの
  var seen=[];
  groups.forEach(function(g){
    sec.querySelectorAll(g).forEach(function(el){ if(seen.indexOf(el)<0) seen.push(el) });
  });
  seen.sort(function(a,b){ return (a.compareDocumentPosition(b) & 4) ? -1 : 1 });
  var cn=0;
  seen.forEach(function(el,n){
    var card=el.classList.contains('card');
    var k = el.classList.contains('tr') ? 'wipe'
          : card ? ((cn++ % 2) ? 'r' : 'l') : 'up';
    el.classList.add('an',k);
    el.style.setProperty('--i', Math.min(n,7));
  });
};
document.querySelectorAll('[data-reveal]').forEach(prep);

/* 2. 位置を見て .on を付け外しする（出す 88% / 戻す 96%） */
var items=[].slice.call(document.querySelectorAll('.an')).map(function(el){return {el:el}});
var rects=new Array(items.length);
var sync=function(){
  var vh=innerHeight,n,on;
  for(n=0;n<items.length;n++) rects[n]=items[n].el.getBoundingClientRect();   // 先に全部読む
  for(n=0;n<items.length;n++){
    var it=items[n], r=rects[n]; on=!!it.on;
    if(!on){ if(r.top < vh*.88) on=true } else { if(r.top > vh*.96) on=false }
    if(on!==!!it.on){
      it.on=on;
      it.el.classList.add('mv');
      it.el.classList.toggle('on',on);
      clearTimeout(it.t); it.t=setTimeout(function(){it.el.classList.remove('mv')},2000);
    }
  }
};
var tick=false;
addEventListener('scroll',function(){ if(tick)return; tick=true;
  requestAnimationFrame(function(){tick=false;sync()}) },{passive:true});
addEventListener('resize',sync); sync(); setInterval(sync,400);   // 見回りが備え

意匠ではありませんが、同じ器の一部として決めておくと後で困りません。

項目値効き方
サイト名WebSite / name検索結果の上に出る名前。入口のページの指定だけが効く。短い名前にする
題<title>太字の見出し。末尾にサイト名を入れない（別枠に出るので重なり、切れる原因になる）
説明meta description薄い文。ただし本文から作り直されることがある
印48 の倍数の四角96 と 192。/favicon.ico も置く
正の住所link rel=canonical同じ内容が複数の住所で出るのを防ぐ
og:site_nameサイト名と同じ入口と各ページでそろえる
og:image1200 × 630寸法も一緒に書く
theme-color地と同じ色スマホの帯が地に溶ける
viewportviewport-fit=cover切り欠きのある端末で端まで敷く

構造化データは役割で分ける

  • WebSite — 入口のページだけ。サイト名のため。
  • Article — 読み物のページ。見出し・説明・日付・書き手。
  • FAQPage — 質問の節をそのまま。検索結果に質問が並ぶことがある。
  • SoftwareApplication — アプリの名前・分類・価格・入手先。

書いた日と直した日（datePublished / dateModified）は、直したときに必ず更新します。
